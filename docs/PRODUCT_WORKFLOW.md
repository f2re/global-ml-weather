# Подготовка спутниковой продукции для модели

## Назначение

Модуль `global_weather.products.workflow` объединяет существующие методы в один проверяемый запуск.
Он читает локальные физические поля, рассчитывает продукцию и собирает входные признаки.
Сеть, декодирование радиосигнала и приборная калибровка в этот запуск не входят.

Продукция уточняет начальное скрытое состояние модели.
Она не подаётся заново на каждом будущем сроке.
Модель сохраняет глобальную динамику и выдаёт профили до 72 часов.
Это не отдельный решатель водного баланса почвы или облачной микрофизики.

## Разделить готовность

`inputs_ready` означает наличие проверенных по контракту файлов.
Этот статус не подтверждает радиометрическую точность или успешное восстановление.
`prepared` означает завершение расчёта и экспорта всех запрошенных продуктов.
`prepared_partial` означает явный отказ одного или нескольких необязательных продуктов.
`blocked` запрещает использование общего снимка для этого выпуска.

Обязательность задаётся в плане, а не назначается алгоритмом задним числом.
При отказе обязательного продукта общий снимок не создаётся.
Остальные рассчитанные поля сохраняются для диагностики.
При прерывании без `snapshot.json` запуск считается незавершённым.

## Продукты и применение

| Продукт | Метод и условия | Применение в модели |
|---|---|---|
| Поверхностная влажность почвы | Инверсия τ–ω; физические H/V температуры; согласованная приборная таблица | Признак состояния поверхности; не готовый поток испарения |
| NDVI поверхности | Красная и ближняя ИК отражательные характеристики после атмосферной коррекции | Растительность; не влажность почвы и не прямое значение LAI |
| NDVI на верхней границе атмосферы | Отдельный метод по отражению до атмосферной коррекции | Самостоятельный признак с отдельными нормами |
| NDMI | Ближний ИК и коротковолновый ИК | Индекс водности растительности; не объёмная влажность грунта |
| NDSI | Зелёная и коротковолновая ИК полосы | Индекс снега; не его масса или толщина |
| Яркостная температура облачного пикселя | Тепловой канал с внешней облачной маской | Наблюдательный признак; не истинная температура верхней границы |
| Высота верхней границы облаков | Скорректированная температура и единственное пересечение профиля | Вертикальное положение облаков; не нижняя граница |
| Водозапас жидкой воды облака | Оптическая толщина, эффективный радиус и подтверждённая жидкая фаза | Интегральная жидкая вода; не водяной пар или лёд |
| Температура поверхности суши | Обращение монохроматического переноса при известных атмосферных членах | Состояние поверхности; не температура воздуха на 2 м |

Точные требования прежних методов описаны в [каталоге продукции](SATELLITE_PRODUCTS.md).
Готовый GeoTIFF или файл SatDump не доказывает пригодность перечисленных входов.

У МСУ-МР есть коротковолновая ИК полоса 1,6–1,8 мкм.
У описанных МСУ-ГС и МСУ-ГС/А такой полосы нет.
Не переносите NDMI по номеру канала между этими приборами.
Широкие спектральные полосы и их реальную калибровку также следует проверять.
Характеристики приборов приведены в источниках ниже.

## Подготовить план

Создайте JSON со схемой `satellite-product-batch-1`.
Укажите время выпуска, происхождение данных и перечень заданий.
Каждое задание содержит идентификатор, продукт, файл расчёта, файл геометрии и Boolean-признак обязательности.
Ссылки на файлы содержат относительный путь и SHA256.

```json
{
  "schema": "satellite-product-batch-1",
  "issue_time": "2026-10-04T12:10:00Z",
  "data_kind": "real",
  "max_records": 100000,
  "items": [
    {
      "id": "soil",
      "product": "soil_moisture_surface",
      "job": {"path": "soil.job.json", "sha256": "ACTUAL_SHA256"},
      "geometry": {"path": "geometry.npz", "sha256": "ACTUAL_SHA256"},
      "required": false,
      "history_hours": 12,
      "min_valid_fraction": 0.01
    }
  ]
}
```

Это пример структуры, не готовое задание с реальными наблюдениями.
Замените время, пути и обозначения хэшей фактическими значениями.
Файл расчёта сохраняет прежнюю схему `satellite-product-job-1`.
Модуль не создаёт недостающие температуру почвы, оптическую толщину или радиус капель.

`history_hours` не может превышать предел метода из каталога.
Пределы являются политикой исследовательского допуска, а не подтверждённой заблаговременностью полезности.
`min_valid_fraction` задаёт долю пригодных пикселей, не долю физической площади.
План допускает до 64 заданий и ограничивает число выходных записей.
Объём общего JSONL ограничен 64 МиБ.
Разбивайте большие области явно; скрытая подвыборка не выполняется.

## Выполнить расчёт

1. Проверьте зависимости.

```bash
python -m global_weather.products preflight --plan data/products/plan.json
```

При отказе обязательного входа команда возвращает код 2.
Физические условия каждого метода дополнительно проверяются во время расчёта.

2. Укажите новый каталог и выполните пакетный расчёт.

```bash
python -m global_weather.products batch --plan data/products/plan.json --output outputs/products/issue-001
```

Не используйте существующий каталог.
При отказе обязательного продукта команда возвращает код 2 и сохраняет причины.
Непригодные значения не заменяются нулями.

3. Проверьте `report.json` и наличие `snapshot.json`.

Отчёт содержит метод, долю пригодных пикселей, причины QC, глубину почвенного слоя через метаданные и долю известных неопределённостей.
Общие зависимости перечисляются отдельно.
Они не считаются независимыми измерениями.

Каталог каждого задания содержит физическое поле `product.npz`.
При успешном допуске он также содержит `observations.jsonl`.
Общий снимок связывает объединённые наблюдения и реестр их контрольными суммами.
Методы экспорта совпадают с фактически выполненными методами расчёта.

## Подключить снимок к существующей модели

Используйте `load_snapshot` для проверки файлов перед сборкой выборки.
Используйте `pack_snapshot` для объединения продукции с наземными и аэрологическими сообщениями.
Оба пути сохраняют прежний контракт `PackedObservations`.

```python
from global_weather.products.workflow import pack_snapshot

observations, registry = pack_snapshot(
    "outputs/products/issue-001/snapshot.json",
    grid,
    pressure_pa,
    normalization=frozen_norms,
    records=station_and_sonde_records,
    variables=station_and_sonde_registry,
)
```

Здесь `grid`, давления, нормы и исходные наблюдения подготовлены существующим конвейером.
Полный реестр модели должен совпадать с возвращённым реестром.
Веса должны быть обучены с этими переменными и методами.
Отсутствие нормы любого продукта блокирует допуск.
Смена метода ковариационной ошибки также меняет реестр и требует совместимой схемы.

Не заменяйте отсутствующую продукцию значением климатической нормы.
Не переносите атмосферные нормы температуры на яркостную температуру или температуру почвы.
Не добавляйте будущую продукцию внутрь начатого прогноза.
Уменьшение ошибки по реальным независимым целям проверяйте отдельным экспериментом.

## Учесть составные продукты

Поле с `metadata.composite: true` требует `metadata.temporal_support`.
Укажите `start` и `end` с часовыми поясами.
Время измерения должно находиться внутри этого интервала.
Конец интервала не может следовать за временем готовности.

Интервал сохраняется в зависимостях продукции.
Самый ранний вход должен помещаться в окно, учтённое при разделении выборки.
Для атмосферных зависимостей учитывается минимум 12 часов.
Более длинная история разрешается только зарегистрированным медленным продуктам.
Свежая обработка старого составного изображения не делает его новым измерением.

## Учесть ковариацию при расчёте LWP

Для однородного жидкого слоя применяется:

`LWP = (2/3) × rho_water × tau × r_eff`.

При наличии ковариации метод использует первый порядок распространения ошибок:

`Var(LWP) = a² × [r² Var(tau) + tau² Var(r) + 2 tau r Cov(tau,r)]`, где `a = (2/3) rho_water`.

Добавьте необязательный вход `covariance` в задание `cloud_liquid_water_path`.
Его величина — `covariance_optical_depth_effective_radius`, единица — `m`.
Это не безразмерный коэффициент корреляции.
Нужны стандартные неопределённости обоих исходных полей.

Проверка требует `abs(Cov) <= sigma_tau × sigma_r`.
Нарушение этого условия маскирует результат.
Отсутствующий ковариационный пиксель также маскируется.
Без входа ковариации остаётся прежний явно условный независимый расчёт.

Расчёт не учитывает все ошибки радиометрии, трёхмерности облака и атмосферной коррекции.
Не называйте полученную неопределённость полной ошибкой восстановления.

```bash
python -m pytest tests/test_product_workflow.py -q
```
