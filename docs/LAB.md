# Стенд испытаний 0.3

## Запуск

Python 3.10+; один локальный процесс, Docker и Node.js для работы не нужны.
В активированной среде с CPU-сборкой PyTorch:

```bash
python -m pip install -e '.[test,data,lab]'
python -m global_weather.lab.app --workspace outputs/lab --port 8765
```

Открыть http://127.0.0.1:8765. Страница, шрифты системы, графика и скрипты локальные.
Стенд не скачивает карты и не обращается к облачным LLM.
На Astra используйте отдельный Python 3.10+; системный Python не заменять.
При отсутствии подходящей версии установщик останавливается, а не меняет ОС.

## Реализованные сценарии

Выбор исходного/адаптивного графа, размеров D/K, сетки 12–642 ячейки, горизонта
до 72 часов, зерна и исключения станций/радиозондов. Запуск одной задачи,
очередь до шести, отмена, таймаут и сохранение результата. Синтетические
оптимизационные шаги проверяют градиенты, но не обучают метеорологии.

Просмотр настоящей геометрии ячеек в ортографической проекции, вращение,
выбор ячейки, поле/уровень/срок и вертикальный профиль. Серый цвет — маска,
не нулевое физическое значение. Гидростатический остаток, нарушения границ,
журнал и скачивание массивов с единицами. RMSE погоды без целей отсутствует.

Вкладка источников показывает возможности и ограничения каждого адаптера.
Загрузка локального файла до 32 МиБ не исполняет его и не даёт допуск в обучение.
Инспекция JSONL проверяет контракт, не удостоверяет калибровку или происхождение.
Существующие файлы не перезаписываются. Имена файлов: латинские буквы, цифры,
точка, дефис, подчёркивание; пути каталогов через HTTP не принимаются.

Вкладки агентов и протоколов показывают актуальные роли/полномочия и документы.
Это не интерфейс управления произвольным Bash и не автономная группа LLM.

## Реальное численное сравнение

`paired_scores` и `python -m global_weather.lab.evaluate` работают с явно
сопоставленными физическими массивами. NPZ: prediction, target, mask(bool),
lead_hours, area_m2, опционально baseline. Форма [срок, ячейка] либо
[срок, ячейка, уровень]. К нему нужен JSON-манифест: variable, units,
target_source, forecast_source, data_kind(real/synthetic), paired_sha256.

```bash
python -m global_weather.lab.evaluate --pairs pairs.npz \
  --manifest pairs.manifest.json --output evaluation.json
```

Получаются MAE, RMSE, смещение и относительное улучшение RMSE к контрольному
прогнозу на тех же целях. Никакой автоматической сертификации независимости.
Это CLI, не подключённый к произвольным внешним прогнозам через веб-интерфейс.

## Хранилище

outputs/lab/experiments.sqlite — статусы и параметры; inbox/ — файлы оператора;
runs/<id>/ — request.json, execution.log, report.json, execution.json,
artifacts.json, grid.npz и frame_000.npz … frame_072.npz. Отчёты фиксируют UTC,
seed, версии, SHA256 Python-файлов и артефактов, исходный commit при наличии.
Вне Git commit может быть null; хэши кода при этом сохраняются.

После перезапуска незавершённые задачи получают interrupted, без автоповтора.
Два процесса на одном рабочем каталоге запрещены. Задания одного стенда
исполняются последовательно. Пакет рассчитан на Linux; RLIMIT и flock не
заявлены переносимыми на Windows.

## Разделение состояния реализации

Реально реализованы код и испытательные сценарии; нет обученных весов,
готового набора норм для всех величин, реальных спутниковых декодеров,
антенного оператора, полной водно-энергетической динамики и промышленной
авторизации. Необученный реальный прогноз через UI не выпускается.

Веб-стенд не публиковать в сеть. Для удалённой работы используйте собственный
аутентифицированный SSH-туннель, не меняя привязку 127.0.0.1. Сетевая загрузка
данных — отдельная команда с --network и лимитами, не кнопка произвольного URL.
