# C2: контрольные точки каждого шага

## Реализованный результат

Модуль `global_weather.continuous.checkpointing` связывает полный снимок обучения с журналом применения примеров.
`StepTrainer` выполняет один шаг оптимизатора и только после сохранения отмечает данные использованными.
Добавлен мост `train_prepared_block` к существующей погодной модели на локальном подготовленном наборе.

Это следующий программный этап после [C1](CONTINUOUS_TRAINING.md), а не весь [непрерывный конвейер](CONTINUOUS_TRAINING_PLAN.md).
Ввод диапазона через HTTP пока только регистрирует работу.
Автоматические проверка источников, подготовка блоков и норм относятся к C3–C5.
Новая графическая страница и спутниковое дообучение не добавлены этой поставкой.

## Что сохраняется

Каждая генерация содержит `state.pt` и `manifest.json`.
Состояние включает модель, оптимизатор, расписание скорости, переданный масштабировщик и режимы модулей.
Сохраняются генераторы Python, NumPy, PyTorch и, для CUDA, состояния генераторов всех видимых устройств.
Паспорт фиксирует шаг, предыдущую генерацию, точный курсор, порядок примеров, использованные записи, метрики и контрольные суммы.

Граница — завершённый шаг оптимизатора.
Исполнитель проверяет, что переданная операция вызвала ровно один шаг.
Незавершённое накопление градиента не объявляется сохранённым шагом.
После исключения сессия закрывается; новая сессия восстанавливает подтверждённое состояние.
Состояние масштабировщика можно сохранить, но мост подготовленных данных использует float32 без автоматического AMP.

Контракт исполнения связывает архитектуру, схему параметров, нормы, оптимизатор, устройство, численные параметры и исходный код.
При несовместимости восстановление блокируется.
Сетка и нормы погодной модели проверяются как неизменяемые буферы.
Публичного HTTP-метода «отметить обученным» нет.

## Фиксация и восстановление

Сначала состояние записывается в новый временный каталог с проверкой конечности тензоров.
Файлы синхронизируются через `fsync`, затем каталог публикуется переименованием и синхронизируется его родитель.
Одна транзакция SQLite фиксирует генерацию, применённые примеры, текущий указатель и событие журнала.
До её завершения данные не считаются обученными.

SQLite работает с WAL и `synchronous=FULL`.
База и блокировка исполнителя требуют локальной файловой системы.
Для одного рабочего каталога разрешён один обучающий процесс и один поток оптимизации.
Файловая блокировка, токен владения и проверка ожидаемой генерации защищают фиксацию от устаревшего исполнителя.

После аварии до транзакции используется прежняя подтверждённая генерация.
После аварии после транзакции сохранённый шаг не применяется повторно.
Пакет, частично совпавший с уже обученными данными, отклоняется; его нужно разделить по журналу.
Повтор целиком выполненного пакета не вызывает функцию оптимизации.

Текущий указатель проверяется против последнего шага и общего числа применённых примеров.
Старая точка не используется с новым журналом.
Повреждение текущего снимка блокирует продолжение; автоматического скрытого отката нет.
Восстановление из проверенной согласованной резервной копии поддержано.
Создание отдельной восстановительной ветви при отсутствии точной резервной копии остаётся дальнейшей задачей.

## Хранение и резервная копия

По умолчанию сохраняются файлы текущей и предыдущей генераций.
Выбранную точку можно закрепить внутренним методом `pin()`.
Старые незакреплённые файлы удаляются только после проверки сохранённых генераций.
История контрольных сумм и применения данных остаётся в базе неизменяемой.
Незавершённые файлы прошлой сессии очищаются при следующем успешном открытии.

Метод `backup()` создаёт отдельный рабочий каталог с согласованными базой и сохранёнными генерациями.
Копия не включает исходные метеорологические массивы, ключи доступа или весь каталог приложения.
Для потери всего накопителя нужен физически независимый носитель резервной копии.
Тест удаления рабочего каталога не имитирует разрушение диска или отказ питания накопителя.
Гарантии зависят от корректного исполнения синхронизации файловой системой и оборудованием.

## Подготовленный блок

Обычному пользователю по-прежнему предназначен будущий сценарий с двумя датами.
Следующие команды нужны для инженерной проверки уже подготовленного локального блока.
Замените путь `data/prepared/dataset.json` фактическим путём своего манифеста.
Используйте отдельное окружение проекта.

```bash
python -m global_weather.continuous --workspace outputs/lab add-range --start-date 2000-01-01 --end-date 2005-12-31
python -m global_weather.continuous --workspace outputs/lab train-prepared --dataset data/prepared/dataset.json --max-steps 1
python -m global_weather.continuous --workspace outputs/lab train-prepared --dataset data/prepared/dataset.json
python -m global_weather.continuous --workspace outputs/lab checkpoints --limit 20
```

Блок должен совпадать с постоянными сеткой, вертикалью, горизонтом и параметрами модели.
Нормы и статические поля фиксируются при первом сохранении; несовместимый следующий блок отклоняется.
Обрабатываются только примеры `train`, одновременно разрешённые постоянной временной политикой программы.
Случайный контрольный или защитный выпуск не обходится принудительным изменением его роли.
Второй вызов пропускает уже зафиксированные применения и продолжает оставшуюся работу.
Намеренный следующий проход задаётся `--pass-number`; он учитывается отдельными событиями.

Мост не запускает сеть, не меняет старый эпохальный тренировщик и не выбирает лучшие веса по тесту.
Независимая оценка этим вызовом не выполняется.
Расчёт новых норм, проверка исторической независимости и автоматический допуск спутников остаются обязательными последующими этапами.

## Наблюдаемость

`GET /api/learning/checkpoints` возвращает ограниченную страницу метаданных поколений.
Маршрут не выдаёт произвольные файлы и не принимает записи.
`/api/learning/state` показывает текущую генерацию и сохранённый шаг.
Суточные блоки показывают число запланированных и зафиксированных применений.
Статус `registered_uses_committed` относится только к зарегистрированным применениям, не к полноте всех данных суток.
Непроверенные каталоги остаются `not_checked`.

## Обновление базы

Первое открытие выполняет добавочную миграцию схемы C1 с версии 1 на 2.
Идентификаторы программы, интервалы, роли, версии источников и намерения использования не пересоздаются.
Неизвестное содержимое зарезервированного журнала контрольных точек C1 блокирует миграцию.
Перед обновлением остановите старый сервер и сохраните согласованную копию рабочего каталога.
Возврат старого кода к базе версии 2 без отдельной миграции не поддержан.

## Проверки и границы

```bash
python -m pytest tests/test_continuous.py tests/test_continuous_checkpoints.py -q
python -m pytest -q
python scripts/check_docs.py --strict
```

Проверяются настоящие аварийные выходы дочерних процессов при вычислении, записи файла, публикации и транзакции.
Сравниваются модель, оптимизатор, расписание, генераторы и курсор.
Отдельно проверяется адаптивная погодная модель на явно синтетических данных с горизонтом 72 часа.
Испытание модели на CUDA требует доступной видеокарты и не подменяется проверкой выбора устройства.
