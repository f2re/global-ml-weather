# Получение спутниковых снимков на вычислительном узле

Применяйте `GLOBAL-WEATHER-REMOTE-1` и [контракт совместимости](ECOSYSTEM.md).
Код разрабатывайте локально. Команды выполняйте на узле, который указал оператор, в рабочей копии проверенного SHA.
Используйте отдельное окружение с `rasterio`. Не изменяйте каталоги и службы поставщиков.

## Требования

CLI использует существующий `SatelliteCatalog` и доверенные сервисы GPTL.
Перед сетевой операцией требуется `--network`.
Токены не передаются через аргументы команды.
При необходимости задайте `--credentials` с путём существующего файла `Credentials` с правами 0600.
Не переносите этот файл в Git или отчёты.

Поиск ограничен семью сутками и 1–10 страницами.
Одна загрузка ограничена 536870912 байтами. Меньший предел задайте через `--max-bytes`.
Каждый паспорт результата сохраняйте в новый файл. Существующий файл CLI не перезаписывает.

## Проверить коллекции

Следующая команда является примером ограниченной проверки каталога без загрузки снимков.
Замените пути каталогами паспорта эксперимента.

```bash
python -m global_weather.providers.satellite_cli \
  --cache data/satellite-cache collections --network \
  --output outputs/satellite-collections.json
```

Проверьте фактические коллекции и идентификаторы платформы.
Не назначайте произвольной платформе имя «Электро-Л».
Доступ к каталогу не удостоверяет право скачивания объекта.

## Сохранить поиск и получить выбранный ресурс

Команды содержат заменяемые примеры времени, коллекции и идентификатора.
Период, пределы и источник должны соответствовать паспорту эксперимента.

```bash
python -m global_weather.providers.satellite_cli \
  --cache data/satellite-cache search --network \
  --start 2026-10-01T00:00:00Z --end 2026-10-02T00:00:00Z \
  --collection VERIFIED_COLLECTION --max-pages 2 \
  --output outputs/satellite-search.json
python -m global_weather.providers.satellite_cli \
  --cache data/satellite-cache download --network \
  --search-report outputs/satellite-search.json \
  --id 00000000000000000000000000000000 --max-bytes 67108864 \
  --output outputs/satellite-download.json
```

Выберите ID из сохранённой выдачи. CLI повторяет тот же запрос перед загрузкой.
Изменение публичных метаданных ресурса блокирует скачивание.
Паспорт содержит публичные результаты и хэш запроса без URI, подписанных ссылок и секретов.
`truncated=true` означает ограниченную выдачу. Даже отсутствие усечения не удостоверяет полноту периода.

Кэш содержит неизменённый файл, `asset.json`, журнал загрузки и контрольную сумму.
Готовый кэш используется после проверки хэша поставщиком.
Время скачивания не является историческим временем оперативной готовности.

## Проверить локальные файлы

Для GPTL-кэша укажите ID скачанного ресурса.

```bash
python -m global_weather.providers.satellite_cli \
  --cache data/satellite-cache inspect-local \
  --id 00000000000000000000000000000000 \
  --output outputs/satellite-cache-check.json
```

Инспекция проверяет размер и SHA256. Она не присваивает физический допуск произвольной платформе.
Для Арктики дополнительно проверяется существующий контракт метаданных L2IR.
Геометрия, нормы и допуск модели остаются отдельными проверками.

Для готовых продуктов Арктики сначала получите локальный список.
Замените путь фактическим каталогом поставщика, доступным для чтения.

```bash
python -m global_weather.providers.satellite_cli \
  --cache data/satellite-cache --arktika-root /path/to/arktika-products \
  inspect-local --output outputs/arktika-products.json
python -m global_weather.providers.satellite_cli \
  --cache data/satellite-cache --arktika-root /path/to/arktika-products \
  import-local --id 00000000000000000000000000000000 \
  --output outputs/arktika-import.json
```

Выберите ID из списка. Импорт повторно просматривает до 200 продуктов.
При усечении списка сузьте корневой каталог до нужного неизменённого продукта.
Импорт копирует готовые файлы без изменения поставщика и повторного применения шкалы.

## Подготовить проверенные ИК-кадры

Для «Арктики-М» подготовьте численные капсулы `physical-raster-v1` через `global_weather.compatibility arktika`.
Для «Электро-Л» используйте `global_weather.compatibility electro-native` с проверенным паспортом `electro-l-native-l2ir-1`.
Проверьте закреплённую ревизию поставщика, идентификатор сцены, платформу и канал.
Подтвердите калибровку яркостной температуры в K, геометрию визирования, размер пятна и нативную маску качества.
Подтвердите начало и конец съёмки по сведениям поставщика.
Подтвердите фактическое время готовности кадра. Время архивного скачивания не заменяет этот срок.
Остановите подготовку при отсутствии любого подтверждения.

В паспорте «Электро-Л» укажите в `files` ссылки на исходный STAC Item `producer_item`, метаданные актива из журнала `asset`, численный GeoTIFF `raster`, квитанцию `download`, отдельный GeoTIFF качества `quality` и геометрию `geometry`.
В `calibration` укажите `revision`, `asset_key` и `reference`. В `quality` укажите `good_flag` со значением 0 и подтверждающую `reference`.
Если STAC Item публикует активы с ролью `quality` или `quality-mask`, в `quality.asset_key` укажите соответствующий нативный актив качества.
В `timing` укажите нативные `scan_start`, `scan_end`, `provider_ready_at` и `reference` для этих сроков.
В этом маршруте срок допуска к прогнозу берётся из проверенной квитанции поступления. Он может быть позже срока готовности поставщика.
Поздно полученная архивная копия сама по себе не доказывает, что кадр был доступен прошлому выпуску.
Путь к паспорту передайте в команду. Предел капсулы составляет 262144 пикселя.
Для большого кадра задайте `window` с полями `row_offset`, `column_offset`, `height`, `width` в исходной сетке данных и качества. Чтение окна сохраняет нативные пиксели и их координаты.

```bash
python -m global_weather.compatibility electro-native "$NATIVE_MANIFEST" --output "$CAPSULE"
```

Создайте план `multimodal-capsule-plan-1` по [руководству многомодальной модели](MULTIMODAL.md#подготовить-данные).
Укажите `data_kind=real` в плане и в реестре прибора.
Для каждого канала задайте ссылки `manifest` и `pixels` на файлы одной капсулы.
Отсутствующий канал обозначьте `null`.
В `declarations.real_admission` укажите ссылку на манифест допуска.
Каждая ссылка имеет форму `{"path": "RELATIVE_FILE", "sha256": "FILE_SHA256"}`.
Пути задавайте относительно каталога плана. В примерах замените пути, хэши, сроки и идентификаторы проверенными значениями.

Манифест допуска `multimodal-ir-admission-1` содержит запись для каждой капсулы плана.
Ключ в `capsules` равен SHA256 файла `manifest.json` капсулы.

```json
{
  "schema": "multimodal-ir-admission-1",
  "capsules": {
    "CAPSULE_MANIFEST_SHA256": {
      "scan_start": "SCAN_START_ISO8601",
      "scan_end": "SCAN_END_ISO8601",
      "available_at": "AVAILABLE_ISO8601",
      "evidence": {
        "origin": {"path": "proof/origin.json", "sha256": "ORIGIN_SHA256"},
        "timing": {"path": "proof/timing.json", "sha256": "TIMING_SHA256"},
        "geometry": {"path": "proof/geometry.json", "sha256": "GEOMETRY_SHA256"},
        "quality": {"path": "proof/quality.json", "sha256": "QUALITY_SHA256"}
      }
    }
  }
}
```

Укажите отдельные файлы JSON для `origin`, `geometry` и `quality`.
В каждом файле укажите `capsule_manifest_sha256`, `source`, `platform` и `native_scene_id` соответствующей капсулы.
В `origin` укажите схему `multimodal-ir-origin-1`.
Перенесите из капсулы `upstream`, `instrument`, `channel_id`, `calibration_reference` и `calibration_status`.
Добавьте подтверждение происхождения и калибровки канала.
Для «Электро-Л» добавьте в `origin.native_manifest` ссылку на паспорт `electro-l-native-l2ir-1`.
Скопируйте `calibration_reference` капсулы в `calibration_id` канала реестра. Идентификатор версии калибровки и SHA256 конкретного кадра хранятся отдельно.
В `geometry` укажите схему `multimodal-ir-geometry-1` и `geometry_reference` из капсулы.
Добавьте подтверждение геометрии и пятна.
В `quality` укажите схему `multimodal-ir-quality-1` и `quality_support` из капсулы.
Для нативных капсул двух источников требуется `quality_support=paired_quality_raster`.
Добавьте подтверждение маски качества.
В `timing` сохраните паспорт времени `multimodal-ir-timing-1`.
В паспорте `source`, `platform`, `native_scene_id` и `observed_at` должны совпадать с капсулой.
Поля `scan_start`, `scan_end` и `available_at` должны совпадать с записью допуска.

```json
{
  "schema": "multimodal-ir-timing-1",
  "source": "arktika_m",
  "platform": "ARCM1",
  "native_scene_id": "PROVIDER_SCENE_ID",
  "observed_at": "NATIVE_OBSERVED_ISO8601",
  "scan_start": "SCAN_START_ISO8601",
  "scan_end": "SCAN_END_ISO8601",
  "available_at": "AVAILABLE_ISO8601"
}
```

Запустите подготовку в отдельном окружении с `rasterio`.
В команде замените пути плана и результата.

```bash
python -m global_weather.multimodal prepare-capsules \
  --plan data/ir/capsule-plan.json --output data/ir/sequence.npz
```

Команда поддерживает общую регулярную географическую сетку без поворота.
Она сохраняет маски каналов и границы съёмки в `sequence.npz`.
Модель допускает кадр, когда вся съёмка входит в 12-часовое окно и кадр готов к выпуску.
Статус `sequence_prepared` подтверждает структуру и согласованность файлов.
Независимую радиометрическую проверку, нормы по train и оценку прогноза выполните отдельно.

## Условия остановки

Остановите соответствующий этап при изменении файла, отказе доступа, неизвестной калибровке или геометрии.
Сохраните ошибку и код возврата. Исключение или таймаут не являются успехом.
Успех CLI подтверждает получение или структуру файла; обучение и точность погоды требуют отдельных испытаний.

Обязательная проверка нового CLI выполняется на узле:

```bash
python -m pytest tests/test_satellite_cli.py tests/test_ecosystem.py -q
```

Тесты с подставным клиентом проверяют программный контракт. Они не удостоверяют реальные спутниковые измерения.

## Контур ассимиляции группировок РФ

Для КА «Электро-Л», «Арктика-М» и «Метеор-М» действует [решение 0021](decisions/0021-russian-satellite-constellation-assimilation.md).
Оно определяет бесшовную сшивку ГСО и ВЭО, калибровку GSICS и операторы МТВЗА-ГЯ и ИКФС-2.
