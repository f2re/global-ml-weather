# Поэтапное обучение по фактическим наблюдениям

Идентификатор решения: `GLOBAL-WEATHER-OBSERVATIONS-1`.
ERA5 остаётся плотным учителем и вторичным диагностическим полем.
Согласие с ERA5 не доказывает независимость от усвоенных ею наблюдений.
ERA5 не является обязательным входом рабочего прогноза.

## Научное основание

[Aardvark Weather](https://doi.org/10.1038/s41586-025-08897-0) разделяет обучение на модули.
Кодировщик сначала восстанавливает анализ из наблюдений под контролем реанализа.
Процессор предварительно обучается на реанализе.
Декодер учится предсказывать реальные наблюдения.
Затем модули дообучаются совместно.

[GraphDOP](https://arxiv.org/abs/2412.15687) обучается и запускается непосредственно по наблюдениям.
Его графы кодировщика и декодера строятся заново по координатам каждого окна.
Модель не требует постоянного перечня станций.
Она прогнозирует значения в произвольных координатах и сроках целевого окна.

[FuXi-DA](https://www.nature.com/articles/s41612-025-01039-3) подтверждает полезность фонового прогноза.
Модель оценивает поправку к фону по спутниковым наблюдениям.
ERA5 используется как обучающая метка, а не как измерение.

Оперативный [4D-Var ECMWF](https://doi.org/10.1002/qj.49712656415) использует наблюдения внутри временного окна.
Наблюдение сравнивается с модельной траекторией в фактический момент измерения.
[Непрерывное усвоение ECMWF](https://www.ecmwf.int/en/newsletter/158/meteorology/continuous-data-assimilation-ifs) дополнительно учитывает поздно поступающие сообщения.

Траектория радиозонда имеет физическое значение.
[Исследование дрейфа](https://doi.org/10.5194/gmd-17-3783-2024) показывает пользу фактических координат и времени каждого уровня.
Зонд может удалиться на сотни километров.
Номинальный срок 00 или 12 UTC не заменяет время запуска и измерения уровня.

## Зачем нужен идентификатор

Идентификатор станции не определяет физическое положение наблюдения.
Он нужен для происхождения, истории прибора, исправлений и поиска повторов.
Он необязателен для пространственного размещения.

Физический ключ содержит координаты, время, величину и вертикальную координату.
Для движущегося зонда используются координаты и время конкретного уровня.
При наличии устойчивого номера сообщения он имеет приоритет.

Порядок выбора идентичности:

| Приоритет | Основа |
|---|---|
| 1 | Идентификатор сообщения поставщика |
| 2 | Идентификатор профиля или запуска |
| 3 | Идентификатор временной платформы |
| 4 | Хэш источника, времени, координат, давления и величины |

Значение и качество не входят в устойчивую идентичность.
Исправление значения оформляется новой ревизией той же записи.
Исправление координат без номера сообщения может создать новую запись.
Это ограничение явно сохраняется в происхождении.

## Этапы обучения

| Этап | Вход | Основная цель | Роль ERA5 |
|---|---|---|---|
| S0 · проверка теории | Плотные поля | Устойчивость ядра, физические диагностики, прогноз до 72 часов | Учитель и плотная проверка |
| S1 · кодировщик наблюдений | Разреженные станции, зонды и спутники | Восстановление анализа | Плотная метка анализа |
| S2 · пространство наблюдений | Фактические наблюдения | Будущие скрытые наблюдения в реальных координатах | Вторичная диагностика |
| S3 · циклический анализ | Предыдущий прогноз и новые сообщения | Будущие наблюдения после обновления состояния | Вторичная диагностика |
| S4 · независимая проверка | Зафиксированные веса | Невидимые профили, платформы, районы и периоды | Дополнительный эталон |

Таблица описывает исходное предложение из main.
Для новых реальных опытов применяйте [решение 0007](decisions/0007-observation-stage-integration.md).
Обучение на фактических полях ERA5 запрещено поручением оператора.
R7 использует закреплённые профильные μ/σ GraphCast по [решению 0010](decisions/0010-graphcast-fixed-normalization.md).
Это исключение не разрешает плотные цели ERA5 или выбор параметров по её проверке.
Программный S0 использует явные синтетические примеры; S1 использует удержанные реальные измерения.
Остальные компоненты наблюдательной схемы сохраняются.
Команда `training-stages` возвращает `execution_implemented=false`.
S0 проверяет работоспособность нейросетевого ядра.
Результат S0 не доказывает работу по фактическим наблюдениям.

S1 следует схеме Aardvark.
Часть модальностей случайно скрывается.
Кодировщик учится работать с пропусками и изменяющейся сетью.

S2 уменьшает зависимость от реанализа.
Функция ошибки рассчитывается в координатах будущих наблюдений.
Целые профили скрываются совместно.
Отдельные уровни одного зонда не делятся между обучением и проверкой.

S3 вводит фон от предыдущего прогноза.
Наблюдения поступают в скользящем окне по фактическому времени.
Поздняя запись используется только после `available_at`.
Уже усвоенная ревизия не применяется повторно.

S4 не изменяет веса.
Основная оценка строится по фактическим наблюдениям.
ERA5 показывает крупномасштабное согласие, но не заменяет наблюдательную проверку.

## Произвольные сроки и координаты

Каждый уровень профиля может иметь собственные:

- время измерения;
- широту и долготу;
- давление;
- набор измеренных величин;
- время готовности;
- качество и ревизию.

Запуск в 03:37 UTC не переносится к 00 или 06 UTC.
Измерение уровня в 04:12 UTC сохраняет этот срок.
Данные попадают в причинное окно выпуска по фактическому времени.

Если уровень содержит время от фактического запуска, вычисляется время уровня.
Номинальный срок не выдаётся за измеренное время запуска.
Отрицательное время подъёма и измерение после получения исходных данных отклоняются.
Если координаты уровня отсутствуют, сохраняются координаты запуска и признак подстановки.
Такая подстановка не объявляется точной траекторией.

Неполный профиль остаётся неполным.
Отсутствующая влажность, ветер или уровень не интерполируются адаптером.
Вертикальное размещение выполняется между соседними уровнями по `ln(p)`.
Экстраполяция за границы оси запрещена.

## Оператор наблюдений

Для обучения S2–S4 нужен оператор `H`:

```text
состояние модели → значение в координате, давлении и времени наблюдения
```

Текущая реализация использует три ближайших центра сферической сетки.
Вес зависит от хордового расстояния между единичными векторами.
Это приближение сферической интерполяции, не консервативный перенос.
Профиль интерполируется по `ln(p)`.
Время интерполируется между соседними кадрами прогноза.

Временная экстраполяция запрещена.
Непригодные маски не становятся нулевыми значениями.
Оператор сохраняет градиент и может участвовать в функции ошибки.
Маскированные NaN не участвуют в сумме; оба соседних уровня давления должны быть пригодны.
Накопленные осадки требуют отдельного интервального оператора и пока отклоняются.
Потери величин с разными единицами нужно считать раздельно и нормировать до объединения.
Компоненты ветра пока интерполируются как скаляры локальной системы.
Корректный векторный оператор для больших расстояний остаётся обязательной последующей задачей.

Первый оператор является проверяемой инженерной основой.
Он не является консервативным объективным анализом.
Полный анализ приращений относится к следующему этапу C4–C5.

## Реализованные модули

| Файл | Назначение |
|---|---|
| `global_weather/observation_identity.py` | Идентичность без обязательного индекса станции |
| `global_weather/providers/upper_air.py` | Нормализация неполного и движущегося профиля |
| `global_weather/analysis/observation_operator.py` | Дифференцируемое сравнение прогноза с наблюдением |
| `global_weather/observation_training.py` | Этапы и групповое разбиение профилей |
| `configs/observation_training_stages.json` | Машиночитаемая политика обучения |

Нормализатор не декодирует TEMP или BUFR.
Декодеры передают ему физические значения и метаданные.
Сетевое получение IGRA и оперативного BUFR остаётся задачей C3.

## Команды проверки

План этапов:

```bash
python -m global_weather.pipeline training-stages
```

Нормализация одного профиля:

```bash
python -m global_weather.pipeline normalize-upper-air \
  --profile profile.json \
  --acquired-at 2026-10-06T12:00:00Z \
  --availability-mode reported \
  --output observations.jsonl
```

Профиль может не содержать `station_id`.
Ему нужны координаты запуска либо координаты уровней.
Для исторического архива без журналов задержки выберите отдельный исследовательский режим.
Не выдавайте предполагаемую задержку за фактическое время поступления.

## Оставшиеся задачи

1. Добавить декодеры IGRA, TEMP и BUFR.
2. Добавить контроль вертикальных скачков и согласованности гидростатики.
3. Реализовать фон от предыдущего прогноза.
4. Реализовать анализ приращений и оценку его неопределённости.
5. Подключить наблюдательную функцию ошибки к C2.
6. Провести испытания на реальных разреженных архивах.
7. Сравнить S2–S3 с ERA5 только как вторичным эталоном.

Успех модульных тестов не подтверждает качество анализа атмосферы.
Нужны наблюдательные эксперименты с исключением целых профилей и районов.

## Обязательность концепции

Все роли разработки применяют [GLOBAL-WEATHER-OBSERVATIONS-1](../agents/OBSERVATION_CONTRACT.md).
Контракт связан с корневым AGENTS и общими правилами ролей.
Проверка связей и согласованности политики включена в полный pytest.
Сам факт успешной проверки связей не доказывает выполнения научных этапов.
