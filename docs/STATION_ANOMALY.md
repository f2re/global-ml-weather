# Опыт прогнозирования приземных аномалий

Постановка: [решение 0014](decisions/0014-surface-climatology-anomaly-supervision.md).
Цель — обучить модель прогнозировать динамику отклонений приземных метеорологических величин от климатической нормы.
Этот паспорт не подтверждает достижение оперативной точности прогноза погоды.
Координатор сохраняет фактический SHA, командные журналы и контрольные суммы отдельно.

## Данные и климатическая нормализация

Наблюдательные входы и цели формируются реальными измерениями станций NOAA GHCNh.
Глобальная сфера, 12-часовая история, 37 уровней и прогноз до 72 часов сохраняются.
Климатические нормы вычисляются строго по обучающей части станций без использования реанализа.
Входы и цели нормируются вычитанием климатической нормы и делением на масштаб изменчивости.
Нейросеть прогнозирует исключительно безразмерное отклонение от климатической нормы.
Физический прогноз восстанавливается сложением климатической нормы и предсказанного отклонения.

## Конфигурация и ресурсы

| Параметр | Значение |
|---|---|
| Конфигурационный файл | `configs/station_anomaly_training.json` |
| Сетка и скрытый размер | mesh 1, hidden 32, зерно 42 |
| Нормализация | Станционная месячная климатология train |
| Цель обучения | Безразмерное отклонение от климатической нормы |
| Эпохи и patience | 20 и 5 |
| Образцы train и validation | 192 и 48 |
| Оптимизатор | AdamW, скорость 0,001, сдвиг 0,01, отсечение 1,0 |
| Усвоение | Оператор Вороного и рекуррентная ячейка GRU |

## Проверка и ограничения

Служба проверяет поступление измерений и активное обновление состояния сетки.
Выбор эпохи осуществляется исключительно по валидационным наблюдательным аномалиям.
Тесты контролируют ненулевые градиенты всех обучаемых параметров модели.
Опыт использует станции с известными координатами без высотной привязки приборов.
Вертикальные профили радиозондов не входят в состав функции потерь этого опыта.

## Фактические результаты обучения

Обучение выполнено на удалённом вычислительном узле `10.7.88.12` на ускорителе NVIDIA RTX 4090.
Использован массив 851 станции NOAA GHCNh с 12-часовым окном входов и прогнозом до 72 часов.
Месячные нормы и шкалы изменчивости рассчитаны строго по обучающей части 2021 года.
Сеть обучена на 20 эпохах с оптимизатором AdamW и контролем градиентов всех 23 обучаемых тензоров.
Лучшей выбрана эпоха 15 с валидационной потерей 0,1645 при обучающей потере 0,1240.
Служба проверила поступление данных, усвоение через ячейки Вороного и прогнозирование отклонений.
Контрольная точка сохранена с хэшем `a1aff011792fb3bf65b10c113a2e268ef87546fd4e6dc7aa6e3d0ba09a8612f6`.
Полный отчёт сохранён в [station-anomaly-training.json](reports/station-anomaly-training.json).

## Фоновый станционный опыт 2023–2026

На вычислительном узле используйте отдельную чистую рабочую копию заданного SHA с окружением `.venv`.
Сохраняйте выбранный SHA в рабочей копии до завершения расчёта.
Проверьте доступность ускорителя перед запуском. По умолчанию скрипт выделяет GPU 1 через `CUDA_VISIBLE_DEVICES`.
Тренер выбирает CUDA при её доступности и CPU в остальных случаях.
Для работы после выхода из SSH у пользовательского менеджера `systemd` должен быть установлен `Linger=yes`.

В примере `VERIFIED_SHA` обозначает полный проверенный SHA рабочей копии.
Флаг `--allow-network` разрешает загрузку NOAA GHCNh за 2023–2026 годы при отсутствии подготовленной выборки.

```bash
bash scripts/run_extended_station_campaign_detached.sh VERIFIED_SHA --allow-network
journalctl --user -u global-weather-station-2023-2026.service
```

Служба проверяет хэши готовой выборки и пригодность окон наблюдений перед обучением.
Если готовой выборки нет, служба загружает GHCNh в отдельный кэш и готовит выборку.
Станционный тренер начинает новый прогон и пишет веса в `outputs/extended_2023_2026/detached-station/training`.
Контрольная точка прежнего прогона не поддерживает проверенное продолжение.
Используйте журнал службы для проверки выполнения после выхода из SSH.
При прерывании обучения сохраните его каталог для проверки контрольных точек.
Повторный запуск с занятым каталогом обучения останавливается до записи весов.

Этот запуск охватывает станционную модель приземных аномалий.
Реальная спутниковая ассимиляция заблокирована по результатам [рецензии S1–S3](reviews/satellite-real-readiness-2026-11-22.md).

## Спутниковое обновление станционного прогноза

Исследовательский режим описан в [решении 0028](decisions/0028-station-satellite-anomaly-pilot.md), выбор источников закреплён в [решении 0029](decisions/0029-station-russian-ir.md).
Он добавляет спутниковые признаки к начальному состоянию станционного прогноза и обучает добавленные модули на измеренных аномалиях.
Зафиксированное станционное ядро служит контрольным методом на общих сроках.

Подготовьте отдельные последовательности с паспортами и назначьте их точным срокам станционного манифеста.
Храните спутниковые файлы и их паспорта рядом с манифестом или в его подкаталогах.
Для «Арктики-М» и «Электро-Л» используйте `station_satellite_data prepare` после [проверки нативных капсул](SATELLITE_ACQUISITION.md#подготовить-проверенные-ик-кадры).
Тренер сверяет массивы входной последовательности с повторной сборкой из капсул.
Рассчитайте нормы по train. Сохраните хэш нового манифеста и независимый паспорт происхождения данных.

Для автономного пилота поместите спутниковый манифест и связанные файлы в отдельный каталог исполнителя под `/var/tmp`.
Фоновый сценарий сверяет ревизию, источники, контрольные суммы и покрытие трёх частей выборки.
Затем он фиксирует нормы, обучает спутниковые модули и запускает отдельный тест лучшей по validation контрольной точки.

```bash
bash scripts/run_station_satellite_detached.sh \
  "$CODE_SHA" "$PYTHON" "$STATION_DATASET" "$STATION_TRAINING" "$RAW_MANIFEST" \
  "$RAW_MANIFEST_SHA" "$STATION_DATASET_SHA" "$STATION_BEST_SHA" "$CLIMATOLOGY_SHA"
```

Укажите абсолютные пути и ожидаемые SHA из проверенных паспортов. Запускайте сценарий от имени владельца данных.
Сценарий выводит имя службы и путь к журналу `station-pilot.log`. Служба выполняет расчёт без сети и продолжает работу после отключения SSH.
Для ручной проверки отдельных этапов используйте соответствующие команды.

```bash
python -m global_weather.station_satellite_data fit \
  --dataset "$STATION_DATASET" --manifest "$RAW_MANIFEST" --output "$FROZEN_MANIFEST"
python -m global_weather.station_anomaly_training \
  --dataset "$STATION_DATASET" --output "$NEW_TRAINING" \
  --config configs/station_satellite_2023_2026_pilot.json \
  --satellite-manifest "$FROZEN_MANIFEST" --base-training "$STATION_TRAINING" \
  --expected-base-sha "$STATION_BEST_SHA" --expected-climatology-sha "$CLIMATOLOGY_SHA" \
  --expected-dataset-sha "$STATION_DATASET_SHA"
```

Здесь пути и SHA обозначают значения из проверенных паспортов конкретного опыта.
Запускайте вычисления в отдельной рабочей копии проверенного SHA под службой `systemd`.
Служба выполняется от имени владельца данных. Для неё задайте время, память и GPU из паспорта запуска.
Остановка или ошибка сохраняет каталог. Повтор используйте с новым каталогом после проверки причины.

После окончания обучения зафиксируйте лучшую эпоху по validation и запустите отдельный тест.
Передайте оценщику тот же спутниковый манифест и SHA лучшей новой контрольной точки.

```bash
python -m global_weather.station_anomaly_evaluation \
  --dataset "$STATION_DATASET" --training "$NEW_TRAINING" --output "$TEST_REPORT" \
  --satellite-manifest "$FROZEN_MANIFEST" --expected-checkpoint-sha "$NEW_BEST_SHA" \
  --expected-climatology-sha "$CLIMATOLOGY_SHA" --device auto
```

Сохраняйте MAE, RMSE, смещение, покрытие общих целей и результат станционного контроля без спутниковых кадров.
