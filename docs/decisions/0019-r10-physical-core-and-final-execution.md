# Решение 0019. Physical-v2 и финальная квалификация R10

Дата: 13 октября 2026 года.
Эксперимент: `joint-mesh8-qualification-r10` / `GLOBAL-WEATHER-MESH8-R10`.
Статус: **реализация физического и запускного контура завершена; реальные Q2/Q3 artifacts и CUDA Q4→Q5 ещё должны быть выполнены на вычислительном узле; научная приёмка запрещена**.

## Причина решения

После фиксации mesh level 8 оставались два класса разрывов. Во-первых, гидростатический decoder ограничивал профиль, но learned dynamics не учитывал явно барический градиент, вращение Земли и устойчивость вертикального перемешивания, а приземный head мог выдавать термодинамически невозможные значения. Во-вторых, диагностика `omega` опиралась на полный Voronoi, которого у memory-bounded mesh8 намеренно нет.

R10 теперь закрывает эти инженерные разрывы до фактического CUDA-запуска. Это не превращает модель в численную гидродинамическую модель и не заменяет независимую метеорологическую верификацию.

## Физическая архитектура

Профильное ядро имеет идентификатор `hydrostatic-primitive-conditioned-v2`, joint-модель — `joint-measured-physical-v2`.

Жёстко выполняются следующие ограничения:

- геопотенциал восстанавливается дискретной гидростатической проекцией на всех 37 изобарических уровнях;
- `0 <= q < 1` обеспечивается параметризацией specific humidity;
- приземная температура положительна;
- точка росы не превышает температуру воздуха;
- станционное давление и MSLP положительны;
- `omega` не обучается на выдуманной цели, а диагностируется после прогноза из уравнения неразрывности в p-координатах.

Learned horizontal exchange теперь обусловлен четырьмя физическими величинами: направлением ветра, расстоянием между центрами ячеек, ускорением от градиента геопотенциала и ускорением Кориолиса. Для построения безразмерного edge weight используется короткий интервал 900 с. Он является только масштабом физического conditioning и не объявляется шагом явной интеграции или CFL-гарантией.

Вертикальная связь latent state зависит от сухой потенциальной температуры. Положительный скачок `theta` вверх уменьшает обмен через устойчивый интерфейс; нейтральная или неустойчивая стратификация его не усиливает сверх базового локального coupling. Это физически мотивированный learned operator, а не явная схема вертикальной турбулентности.

## Что намеренно не заявляется

Physical-v2 не считается решателем примитивных уравнений. В R10 нет доказательства точного сохранения полной массы, влаги или энергии, нет замкнутого нижнего граничного условия для вертикального движения, нет CFL-доказательства устойчивости и нет доказанного метеорологического разрешения 27,9 км. Геометрический масштаб mesh8 остаётся только `sqrt(mean cell area)`.

## Mesh8 continuity и omega

Для уровней с материализованным `SphericalVoronoi` сохраняется точная Voronoi-edge геометрия. Для mesh8 используется согласованная с его площадями barycentric vertex-centred control volume:

1. для каждого primal edge находятся два соседних сферических треугольника;
2. dual boundary проходит от центра первого треугольника через midpoint primal edge к центру второго;
3. один и тот же поток добавляется двум соседним ячейкам с противоположными знаками;
4. горизонтальная дивергенция вычисляется по площади ячейки;
5. `omega` интегрируется вниз из условия `omega(100 Pa)=0` по `div_h(V) + d(omega)/dp = 0`.

Edge processing выполняется чанками, по умолчанию 32768 рёбер, а давление — по четыре уровня. Поэтому Q5 не материализует массив порядка `1 966 080 × 37 × 3`. Отсутствующий wind support инвалидирует только непосредственно связанные control volumes и не распространяется по графу вследствие порядка обхода.

Для mesh8 forecast physics по умолчанию работает in-place на только что собранном disposable forecast tensor и не создаёт вторую гигабайтную копию профилей.

## Диагностики Q5

Каждый `completion.json` обязан содержать:

- hydrostatic residual: count, RMS и max absolute;
- pressure-continuity residual: count, RMS и max absolute;
- диапазон specific humidity и число нарушений физического диапазона;
- area-integrated shared-flux closure на полностью поддержанных срезах;
- common-support water-mass proxy;
- common-support dry-static-energy proxy;
- common-support kinetic-energy proxy.

Последние три являются диагностическими интегралами в p-координатах на общей маске сроков и не считаются доказательством точного закона сохранения.

## Финальные технические gates R10

R10 выполняется только последовательностью:

`preflight → Q4 CUDA train/validation → Q5 frozen inference/physics/GRIB2 → final evidence gate`.

`global_weather.mesh8_preflight` проверяет точный clean Git SHA, реальный fingerprint всех 655362 ячеек, dataset verify, 72-часовой split guard исходного joint archive, GraphCast normalization provenance, climate artifact, static terrain artifact, CUDA и заявленный memory budget, а также минимум 64 GiB свободного диска. Симлинки в путях артефактов запрещены.

`scripts/mesh8-r10-runner.py` не принимает исполняемые команды из manifest/config. Последовательность команд зафиксирована в source и выполняется на `CUDA_VISIBLE_DEVICES=0` с абсолютным deadline, контролем диска, сохранением stdout/stderr и хэшами журналов.

`global_weather.mesh8_final_check` разрешает только технический статус `r10_q4_q5_technically_qualified`, если:

- best checkpoint совпадает с опубликованным SHA256;
- фактические CUDA peak allocated/reserved записаны;
- все trainable branches имеют конечные ненулевые gradients;
- source revision, mesh fingerprint и physical-v2 architecture совпадают с preflight;
- Q5 содержит ровно сроки 0 и +3 ч;
- specific humidity domain violations равны нулю;
- `max |hydrostatic residual| <= 5 m2 s-2`;
- `max |continuity residual| <= 1e-6 s-1`;
- NPZ, GRIB2 и inventory проходят SHA256 verification.

Эти thresholds являются техническими R10 gates. Они не являются стандартами метеорологической точности.

## Переход к 72 часам

Успешный R10 не повышает текущий experiment до 72 часов. Следующий опыт получает новый идентификатор и допускается только после измеренной CUDA-телеметрии R10, разработки streaming/checkpointed rollout и streaming export, а затем независимой проверки RMSE/MAE/ACC и физических диагностик по срокам и уровням.

Команды подготовки и запуска зафиксированы в `docs/MESH8_R10_FINAL_RUN.md`.
