# Контракт данных 0.2

Базовые поля физических сообщений, геометрия, калибровка и требования к целям
сохраняются из [контракта 0.1](archive/DATA_CONTRACT-v0.1.md).

Дополнения:

- `pack_observations(..., normalization=bundle)` нормализует только пригодные
  физические значения, не изменяя их исходную запись или физические единицы.
  Все объявленные в реестре величины должны иметь проверенные нормы.
- `PackedObservations.normalization_fingerprint` фиксирует выбранный набор норм;
  он также включён в `schema_fingerprint`. Нельзя смешать одну нормировку входов
  с другой нормировкой выхода/контрольной точки.
- `evidence_ids` содержит стабильную идентичность каждой версии измерения.
  Идентичность включает источник, ID, ревизию и время доступности. Она повторяется
  на двух вертикальных связях одного наблюдения, не превращая их в два измерения.
- При циклическом анализе уже усвоенные версии не применяются повторно. Новая
  ревизия должна менять номер; молчаливое изменение значения с прежним ID и
  ревизией является нарушением контракта.
- Фоновое состояние обязано иметь точное время текущего анализа и ту же схему.
  Перенос выполняется только шагом обученного ядра. Будущие фактические данные
  запрещены внутри прогнозного выпуска.

Климатическая норма не заполняет фактические пропуски. Отсутствие измерения,
подземный уровень, отсутствие цели и маска продукции остаются разными понятиями.
Геометрия и физическая площадь микроволнового измерения не исчезают из-за
нормализации. Недостающий антенный оператор по-прежнему не заменяется точкой.

Скалярные инженерные offset/scale из 0.1 остаются только для явно синтетической
демонстрации и сравнительного базового кода. Рабочая адаптивная модель без
`NormalizationBundle` не создаётся, кроме явного `allow_unscaled_synthetic=True`.

Подробная схема норм: [NORMALIZATION.md](NORMALIZATION.md).
