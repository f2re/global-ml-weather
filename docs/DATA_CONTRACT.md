# Контракт данных

## Назначение

Контракт сохраняет физический смысл, время и происхождение каждого значения.
Базовые поля JSONL и целей описаны в [контракте 0.1](archive/DATA_CONTRACT-v0.1.md).
Текущие дополнения относятся к нормам, памяти анализа и импорту растров.

## Наблюдение

Одна строка JSONL содержит одно скалярное измерение.
Укажите величину, значение, единицу, координаты, источник и версию.
Укажите время наблюдения и время готовности с часовым поясом.
Для уровня радиозонда укажите фактическое давление, время и доступные координаты.

Индекс станции является метаданными происхождения, но не условием допуска.
Незарегистрированный запуск допускается по координатам и времени сообщения.
При наличии устойчивого номера сообщения он определяет идентичность профиля.
Иначе используется хэш поставщика, времени запуска и начальной позиции.

Каждый уровень движущегося зонда может иметь собственные координаты и время.
Номинальный срок 00 или 12 UTC не заменяет фактическое время запуска.
Измерение между штатными сроками сохраняет точный момент и попадает в причинное окно.
Если траектория неизвестна, координаты запуска отмечаются как подстановка, а не точное положение.

Для выпуска `t` допустимо только окно `(t−12 ч, t]` и `available_at <= t`.
Время строки спутника, время сцены и время получения не взаимозаменяемы.
Не достраивайте неизвестное время по имени файла.
Не заполняйте отсутствующую величину реанализом.

Отсутствующее значение пропустите либо пометьте `valid=false`.
Булевы поля должны быть настоящими значениями JSON, а не строками.
Ноль не является общей меткой отсутствия.
Каждая величина и уровень имеют собственный устойчивый идентификатор.
`observation_id` можно передать явно либо получить из координатного контракта.
Значение и оценка качества не входят в устойчивую идентичность.
Изменение значения требует новой версии.

## Нормы

`pack_observations(..., normalization=bundle)` преобразует пригодные физические значения.
Исходная запись и единица сохраняют свой смысл.
Все переменные реестра должны иметь проверенные нормы.

`normalization_fingerprint` фиксирует набор норм и входит в `schema_fingerprint`.
Сетка, давления, переменные и нормы должны совпадать с моделью и контрольной точкой.
Несовпадение блокирует обработку.

Инженерные `offset/scale` исходной демонстрации не являются нормами рабочих наблюдений.
Адаптивная модель требует `NormalizationBundle`, кроме явно синтетического режима `allow_unscaled_synthetic=True`.
[Порядок подготовки норм](NORMALIZATION.md).

## Память анализа

`evidence_ids` содержит идентификаторы усвоенных версий.
Идентификатор включает источник, ID, ревизию и время доступности.
Две вертикальные связи одного измерения не превращаются в два независимых наблюдения.

Повторяющаяся версия не усваивается повторно из перекрывающегося окна.
Фон должен иметь точное время нового анализа и совпадающую схему.
Перенос выполняется шагом обученного ядра.
Не добавляйте будущие фактические наблюдения в начатый прогноз.

## Спутниковые данные

Для физического канала сохраните прибор, платформу, калибровку, единицу и геометрию.
Цифровой отсчёт, изображение RGB и яркостная температура являются разными величинами.
Нормализация не устраняет размер антенного пятна.
Отсутствующий антенный оператор нельзя заменить точечным измерением.

Импорт `arktika-worker` читает `values.tif` без повторной шкалы и сохраняет `quality.tif` как маску.
Импорт GPTL сверяет файл с `.download.json` и применяет шкалу один раз.
Эти адаптеры допускают только определённый контракт ИК-каналов.
Полные требования: [совместимость](ECOSYSTEM.md).

Промежуточный набор `physical-raster-v1` содержит массивы и манифест с SHA256.
Без проверенной геометрии он не экспортируется в наблюдения.
Экспорт JSONL не является окончательным допуском в модель.
Реестр канала, нормы, временное окно и размер пятна проверяются следующим этапом.

## Цели обучения

`training.Targets` содержит сроки, физические массивы и отдельную маску каждой величины.
Сетка и ось давления должны совпадать с моделью.
Каждое значение с маской `true` должно быть конечным.
Подземные уровни маскируются по целевым данным, а не по прогнозу давления.

У анализа с заблаговременностью 0 нет будущего интервала осадков.
При шаге три часа цель +3 часа описывает сумму за `(t, t+3 ч]`.
Цель +6 часов описывает сумму за `(t+3 ч, t+6 ч]`.
Не делите шестичасовое измерение на произвольные трёхчасовые цели.

Интерполяция реанализа не создаёт истинную мелкомасштабную цель.
Для фактических наблюдений используется оператор координата–давление–время.
Он поддерживает станции, незарегистрированные зонды и движущиеся платформы.
Текущая реализация не является полным объективным анализом приращений.
[Поэтапное наблюдательное обучение](OBSERVATION_DRIVEN_TRAINING.md).
