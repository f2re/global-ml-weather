# Совместимость с проектами пользователя

## Область проверки

Контракт основан на исходниках, проверенных 3 октября 2026 года.

| Поставщик | Ветка | Ревизия |
|---|---|---|
| `f2re/arktika-worker` | `main` | `4d744570653ac60c8fd059d10e617c3806a6bafc` |
| `f2re/SatDump` | `release/1.2.2` | `394431e11d9fffe1a73d3e0670fb023ad7562241` |

Ревизии и хэши контрактных файлов записаны в `configs/ecosystem_sources.json`.
Исходная ревизия не удостоверяет установленный бинарный файл, его ресурсы или TLE.
Не приравнивайте BOARD 22 к последующим исправлениям ветки без проверки.
Рабочие приёмники, серверы и реальные спутниковые проходы здесь не испытывались.

## Уровни готовности

Прочитанный формат не является откалиброванным измерением.
Импорт сохраняет численные значения, маску, координаты, время и хэши.
Для экспорта наблюдений дополнительно требуется проверенная геометрия.
Для допуска в модель требуются реестр каналов, нормы, временное окно и оператор наблюдения.
Импортёр не присваивает этот допуск автоматически.

## Проверить исходные копии

Установите зависимости в отдельное разрешённое окружение.
Замените пути в примерах своими каталогами.

```bash
python -m pip install -e '.[test,data,lab,ecosystem]'
python -m global_weather.compatibility checkout /path/to/arktika-worker --upstream arktika-worker
python -m global_weather.compatibility checkout /path/to/SatDump --upstream satdump
```

Команда проверяет HEAD, ветку либо закреплённый отсоединённый коммит, чистоту копии и выбранные файлы.
Ожидаемый статус — `pinned_source_match`.
При `review_required` повторите аудит поставщика. Не изменяйте закреплённый SHA только ради успешной проверки.

## Импортировать продукт Арктики

Сохраните вместе `product.json`, `values.tif` и `quality.tif`.
`values.tif` уже содержит физические значения. Не применяйте его исходные `scale/offset` повторно.
`quality.tif` должен совпадать по сетке с численным растром.

Поддержаны продукты `channel` для ARCM1/ARCM2, ИК-каналы 4–10 и подтверждённые единицы K.
RGB, разности, классы, `assumed` и неизвестное время не допускаются как исходный канал.
`display.tif` и `map.png` служат отображению, а не заменяют измерения.

Команды ниже содержат примеры путей и времени.
Укажите фактическую готовность после обработки и ссылку на её журнал.
Не используйте время изменения файла как единственное доказательство.

```bash
python -m global_weather.compatibility arktika /path/to/product/product.json \
  --available-at 2020-01-01T01:00:00Z \
  --availability-reference /operator/logs/processing-event-id \
  --geometry /path/to/reviewed-geometry.json --output data/bridge/scene9
python -m global_weather.compatibility export data/bridge/scene9 \
  --output data/bridge/scene9.jsonl
```

Без `--geometry` импорт сохраняет промежуточный растр.
Экспорт наблюдений при этом блокируется.
Геометрическое дополнение содержит `reference`, `view_zenith_deg` и `footprint_km`.
Значение может быть скаляром либо массивом формы растра.
Оно должно происходить из проверенного расчёта геометрии.
Не назначайте нулевой угол или размер ячейки как замену неизвестному измерению.

Время сохраняет признак `native_scene_time_not_per_pixel_time`.
Отсутствующее построчное время не восстанавливается по географии.
Зарегистрируйте имя `source:platform:instrument:channel` с `vertical=column`.
Добавьте собственную фиксированную норму этого канала.
Инженерную нормировку синтетического теста не переносите в рабочую модель.

## Импортировать Электро-Л из GPTL

Используйте уже скачанный L2IR, исходный `.download.json` и объект `normalize_asset` либо элемент STAC.
Новый доступ или новый сетевой клиент не создаётся.
Платформа сохраняется без переименования.
Текущий интерфейс `arktika-worker` ориентирован на ARCM1/ARCM2; наличие в нём кнопки «Электро-Л» не заявляется.

```bash
python -m global_weather.compatibility gptl /path/to/item.json \
  --asset-key exact-provider-asset-key --channel 9 \
  --raster /path/to/channel.tif --source electro_l \
  --available-at 2020-01-01T02:00:00Z --availability-reference /operator/event \
  --geometry /path/to/geometry.json --output data/bridge/electro9
```

Для нормализованного объекта параметры `--asset-key` и `--channel` не нужны.
Для STAC выберите ресурс и проверенный физический канал явно.
`asset_id`, размер и SHA256 должны совпасть с журналом.
Журнал фиксирует окончание загрузки, а не время съёмки или готовность до обработки.
Шкала применяется один раз. `nodata` исключается до преобразования значения.

Поддерживается только явный контракт L2IR.
HRIT, произвольные L1, L3BT9, RGB и видимые каналы требуют отдельного адаптера.
Не угадывайте единицы и уровень обработки по имени файла.

## Проверить набор SatDump

```bash
python -m global_weather.compatibility satdump /path/to/output/dataset.json --require msu_mr mtvza
```

Можно передать `dataset.json` либо отдельный `product.cbor`.
Проверка читает ссылки `images[].file/name`, наличие байтов, обязательные приборы, раскладку и отчёты.
Она не декодирует изображение и не выполняет C++-движок.

`hrpt30` содержит 30 транспортных каналов, `dump46` — 46.
Эти раскладки не являются взаимозаменяемой таблицей физических частот.
`timestamp=-1` означает неизвестное время.

Статус `native_transport_only` не разрешает обучение на цифровых отсчётах.
Наличие ключей калибровки, проекции или TLE не подтверждает выполнение соответствующих преобразований.
`save_as_matrix`, время и геолокация требуют поддержанного нативного обработчика.

МТВЗА требует физической калибровки, таблицы каналов и антенного оператора.
Рецепты Rainfall, Sea Ice и Soil Moisture не принимаются как измерения этих величин.
МСУ-МР требует собственного проверенного пути калибровки и геометрии.

## Выход и условия остановки

Импорт создаёт `pixels.npz` и `manifest.json` без изменения каталога поставщика.
Существующий результат не перезаписывается.
Отсутствие геометрии сохраняется как явная причина блокировки экспорта.
Изменение файла, неизвестный формат, несовпадение единиц или хэша останавливают затронутый этап.
Остальные пригодные источники не удаляются.
