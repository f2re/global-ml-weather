# Постоянная программа: реализованная часть C1

[План](CONTINUOUS_TRAINING_PLAN.md) и [контракт](../agents/CONTINUOUS_TRAINING_CONTRACT.md) определяют полный сценарий.
Эта поставка реализует хранение постоянной программы, диапазонов, версий примеров и журнала намерений использования.
**Регистрация дат ещё не запускает непрерывное обучение.** Подготовка источников и новая графическая страница остаются следующими этапами.
Сохранение каждого шага и обучение локального подготовленного блока добавлены в [C2](CONTINUOUS_CHECKPOINTS.md).

## Что выполняется

Первый диапазон создаёт одну постоянную программу в выбранном рабочем каталоге.
Новые диапазоны продолжают ту же программу и её неизменный научный контракт.
Интервалы объединяются без повторной постановки календарных дней.
Ограничения в 366 суток нет; многолетний период хранится несколькими строками, а не полным списком дней.

Повтор одного запроса возвращает прежнюю квитанцию.
Одинаковый ключ с другими датами отклоняется.
Регистрация диапазона и событие журнала фиксируются одной транзакцией.
Запрос не создаёт веса, не запускает сеть и не выдаётся за старт обучения.

Интерфейсы чтения возвращают ограниченные страницы диапазонов, блоков, примеров и событий.
Блок имеет устойчивую идентичность по программе и дате UTC.
Непроверенная обеспеченность остаётся `not_checked`, подготовка и обучение — `not_started`.

## Использование командной строки

Выполните команды из отдельного окружения проекта:

```bash
python -m global_weather.continuous --workspace outputs/lab add-range --start-date 2000-01-01 --end-date 2005-12-31
python -m global_weather.continuous --workspace outputs/lab add-range --start-date 2004-01-01 --end-date 2010-12-31
python -m global_weather.continuous --workspace outputs/lab state
python -m global_weather.continuous --workspace outputs/lab blocks --limit 30
python -m global_weather.continuous --workspace outputs/lab events --after 0 --limit 100
```

В примере первая квитанция содержит 2192 дня.
Второй диапазон пересекает 731 ранее зарегистрированный день и добавляет 1826 новых дней.
Идентификатор программы сохраняется после завершения команды и перезапуска процесса.
`new_days_at_registration` относится к моменту исходной регистрации, а не к повторному чтению квитанции.

При пагинации передавайте `next_after` либо `next_after_date` из предыдущего ответа.
Отсутствующее продолжение возвращается как `null`.
Дни вне порученных диапазонов автоматически пропускаются, включая большие разрывы между годами.

## Локальный API

Маршруты включены в существующий сервер `global_weather.lab.app`.
Действуют прежние Host, CSRF и CSP; произвольные пути и команды не принимаются.

| Метод и маршрут | Содержание |
|---|---|
| `POST /api/learning/ranges` | Только `start_date` и `end_date`; даты включаются целиком по UTC |
| `GET /api/learning/state` | Постоянная программа, зарегистрированные дни, примеры и граница реализации |
| `GET /api/learning/ranges` | Квитанции, курсор `after` и предел `limit` |
| `GET /api/learning/blocks` | Суточные блоки, `after_date` и `limit` |
| `GET /api/learning/events` | События с последовательным курсором |
| `GET /api/learning/samples` | Зарегистрированные версии примеров и число намерений использования |

Заголовок `Idempotency-Key` необязателен; без него ключ вычисляется из двух дат.
Требуемый `X-Lab-CSRF` берётся из существующего `/api/bootstrap`.
Неизвестные поля запроса, например список станций или команда, отклоняются.
Ответ содержит `training_started=false` и `registered_waiting_for_executor`.
Вызов не подменяет кнопку обучения в прежнем интерфейсе `/experiments`.

## Временные роли и версии данных

Политика `monthly-ranked-v1` резервирует восемь обучающих, два проверочных и два тестовых месяца каждого года.
Порядок определяется SHA256 года, месяца и постоянного зерна, независимо от текущего запроса.
Это не фиксированный выбор одного сезона для всех лет.
Фактические доли сроков отличаются из-за длины месяцев и защитных интервалов.

Пригодный выпуск должен целиком помещаться в одну роль вместе с 12-часовой историей и 72-часовым горизонтом.
Пересечение границы другой роли даёт `guard`.
Контрольные и защитные примеры нельзя поставить в журнал намерений обучения.
Запрет повторён ограничением базы, а не только проверкой Python.

Это разбиение исследовательских временных блоков, не доказательство строгой ретроспективной независимости.
Выполнение C5 должно отдельно проверить периоды норм, выбора весов и использования контрольных результатов.
Проверки старого `PreparedDataset` не изменены и не отключены.
Смена политики существующей программы без миграции запрещена.

Внутренний метод `register_sample()` принимает версии входов, целей, модальности, срок и хэш преобразования.
Идентичность не зависит от порядка источников, записи часового пояса и границ запроса.
Новая ревизия либо контрольная сумма источника создаёт другую версию примера.
Старые записи не перезаписываются.

Регистрация описания не удостоверяет физическую пригодность файлов; требуется последующая проверка C3–C6.
Метод `plan_use()` создаёт отдельное намерение для каждого разрешённого прохода.
Повторное намерение того же прохода не дублируется.
Статус `planned_not_trained` не является записью применения градиента.

## Долговечность и границы

База находится в `WORKSPACE/continuous/learning.sqlite3`.
Используются WAL, `synchronous=FULL`, включённые внешние ключи и транзакции `BEGIN IMMEDIATE` [S1–S3].
Размещайте базу на локальной файловой системе, не на сетевом диске [S4].
Файлы данных могут храниться отдельно; это не меняет требования к SQLite.

История кампании, ролей, описаний и событий защищена от перезаписи и удаления через SQL-триггеры.
Это защита от ошибок программы, не изоляция от владельца локального файла.
Символические и жёсткие ссылки для базы и её служебных файлов отклоняются.
Неизвестная версия схемы не сбрасывается и не переинициализируется.

В C1 таблицы фактических применений были зарезервированы без записывающего исполнителя.
Теперь [исполнитель C2](CONTINUOUS_CHECKPOINTS.md) согласованно сохраняет состояние и журнал применения локальных подготовленных примеров.
Он поддерживает восстановление после прерывания и согласованную резервную копию без исходных погодных массивов.
HTTP-маршрута произвольной фиксации обученного шага нет; автоматическая подготовка по датам остаётся следующей задачей.

## Проверки

```bash
python -m pytest tests/test_continuous.py -q
python -m pytest -q
python scripts/check_docs.py --strict
```

Проверяются многолетний диапазон, пересечения, повторы, конкурирующая регистрация и настоящий аварийный выход отдельного процесса внутри SQLite-транзакции.
Отдельно проверяются постоянные роли, защитные интервалы, версии источников и запрет записи контрольных примеров в обучение.
Тестовые описания источников являются контрактными примерами; они не выдаются за реальные наблюдения.

[Задания по ролям](../agents/tasks/continuous-c1.md) обозначают области ответственности.
Они не подтверждают запуск отдельных агентов или независимую проверку.
