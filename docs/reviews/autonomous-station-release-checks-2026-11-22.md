# Проверки выпуска станционного опыта 2023–2026

Дата подготовки — 22 ноября 2026 года. Роль — `release-auditor`.
Этот перечень задаёт условия приёмки и состав доказательств.
Журналы исполнения и решение о выпуске оформляются отдельно.

## Завершение фонового обучения

1. Сверьте испытанный SHA, состояние рабочей копии, каталог опыта и конфигурацию запуска.
2. Сохраните журнал службы с момента запуска и проверьте сообщения после закрытия SSH.
3. Сверьте код завершения процесса и статус `surface_climatology_anomaly_research_trained` в `complete.json`.
4. Сверьте лучшую эпоху в `complete.json` и `best.json`.
5. Проверьте SHA256 контрольных точек из `best.json` и `latest.json`.
6. Сохраните хэши конфигурации, списка станций, манифеста данных, источников, норм и станционной климатологии.

Выполните команды в рабочей копии испытанного SHA на вычислительном узле.
`TRAINING_DIR` и `DATASET_DIR` обозначают фактические каталоги завершённого расчёта.

```bash
git rev-parse HEAD
git status --short
journalctl --user -u global-weather-station-2023-2026.service --utc --no-pager
sha256sum "$DATASET_DIR/dataset.json" "$DATASET_DIR/norm.json" \
  "$TRAINING_DIR/complete.json" "$TRAINING_DIR/best.json" "$TRAINING_DIR/latest.json" \
  "$TRAINING_DIR/station_climatology.npz" configs/station_anomaly_extended_2023_2026.json \
  assets/admission_851_stations.json
```

Возьмите имя службы и журнал из паспорта конкретного запуска.
Если диспетчер уже выгрузил временную службу, сверьте журнал завершения и артефакты с одним идентификатором запуска.
Сверьте лучшую валидационную потерю из `complete.json` с `metrics.json` лучшей эпохи.
Сверьте SHA256 файлов `state.pt` со ссылками на контрольные точки.
Сохраните UTC начала и конца, устройство, ограничения, версии, зерно, команды и коды возврата.

## Отложенный станционный тест

1. Утвердите протокол и зафиксируйте SHA весов лучшей валидационной эпохи до подсчёта итоговых показателей.
2. Проверьте в манифесте границы train, validation и test, 12-часовые входы и 72-часовые цели.
3. Проверьте отсутствие пересечений между входными и целевыми окнами разных частей.
4. Запустите оценку только на test в отдельном процессе с фиксированными весами и нормами.
5. Сохраните SHA оценщика, данных, весов и результата.

Для этого опыта train охватывает 2023–2024 годы, validation — 2025 год, test — январь–сентябрь 2026 года.
Точные границы и допустимые окна определяет код подготовки данных. [Разбиение](../../global_weather/observation_data.py).

Выполните команду из отдельного окружения `.venv`.
Возьмите `BEST_SHA` из проверенной ссылки `best.json`. Укажите новый `TEST_REPORT` для отчёта.
Зафиксируйте SHA256 станционной климатологии в `CLIMATOLOGY_SHA` до оценки.

```bash
.venv/bin/python -m global_weather.station_anomaly_evaluation \
  --dataset "$DATASET_DIR" --training "$TRAINING_DIR" --output "$TEST_REPORT" \
  --expected-checkpoint-sha "$BEST_SHA" --expected-climatology-sha "$CLIMATOLOGY_SHA" --device auto
sha256sum "$TEST_REPORT"
```

Сверьте MAE, RMSE, смещение, число целей и покрытие отдельно по величинам и заблаговременности, включая +24, +48 и +72 часа.
Сравните с климатологией train и сохранением последнего доступного измерения на общих масках целей.
Укажите единицы, правила взвешивания, сезоны и ограничения пространственного покрытия.
Для вывода о преимуществе оцените неопределённость парных различий по погодным эпизодам.
Фактические поля ERA5 допускаются только в отдельной проверке зафиксированной модели.

Оценка охватывает приземные величины на станциях. Профильная ветвь в этом опыте не получает измеренных целей.
Время готовности части архивных станционных данных оценивается по допущению о задержке. Оперативные задержки требуют отдельной проверки.
Характеристики других периодов, областей и измерительных высот требуют собственных доказательств.

## Инженерная приёмка

Включите отдельное окружение на вычислительном узле. Используйте новые каталоги выходных файлов для каждого испытанного SHA.

```bash
python -m pytest -q
python -c 'import rasterio'
python -m pytest tests/test_ecosystem.py tests/test_agent_contracts.py tests/test_pipeline.py tests/test_reference_assets.py -q
python -m global_weather.cli train-smoke --optimizer-steps 2 --horizon-hours 72 --output outputs/baseline-check
python -m global_weather.adaptive_cli --horizon-hours 72 --output outputs/adaptive-check
python -m global_weather.multimodal selftest --output outputs/multimodal-check
python scripts/pipeline-test.py
python scripts/check_docs.py --strict
python -m global_weather.compatibility release-gate "$EVIDENCE_JSON"
```

Заполните [шаблон доказательств](../protocols/release-evidence.template.json) фактическими отчётами исполнителя и независимого рецензента.
Укажите один испытанный SHA и SHA256 каждого отчёта. Проверьте статус `engineering_evidence_complete`.
На итоговом SHA проверьте задания процессов `tests`, `prepared-data-pipeline`, `multimodal-integration` и других применимых процессов из `.github/workflows`.
Включите журналы обоих браузерных сценариев из `tests` и проверку браузерного конвейера из `prepared-data-pipeline`.
Перед прямым продвижением повторно прочитайте `main`. Остановите перенос при отсутствии обязательного результата или изменении базы. [Порядок публикации](../../agents/PUBLICATION_CONTRACT.md).

5. Покажите, что модель усваивает реальные кадры и использует их в отдельном прогнозном испытании.
