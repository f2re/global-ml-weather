# Согласование двух реализаций R9 перед слиянием

Дата: 10 октября 2026 года.
Оператор поручил перенести R9 в основную ветку.
После прежней проверки main продвинулась и содержит собственную реализацию R9.

## Исходные ревизии

| Роль | Коммит |
|---|---|
| Общая база | `9af374c45dc7e237e6a796a7674008eed95f9038` |
| Гидростатическая ветка PR 10 | `680cc83a37c648caa09bfa80392aa7776441b347` |
| Дополнение main | `89a8c0dc5032e3dfc30f3b5bcc501c78fa38850e` |

Прямой перенос прежнего HEAD ветки заменил бы новое изменение main.
Вместо этого готовится коммит с обоими родителями и согласованным деревом.
Принудительная перезапись истории не применяется.

## Сохранённые варианты

| Вариант | Настройки | Поведение |
|---|---|---|
| R9 из main | `profile_r9_training.json` | Порог целей q 300 гПа, взвешенный MSE, опциональная мягкая гидростатика |
| R9-L | `profile_r9_loss.json` | Проверка пар T/q/p, Хьюбер и профильное усреднение |
| R9-H | `profile_r9_hydrostatic.json` | Та же политика и гидростатический декодер по построению |
| R9-M | `profile_r9_mesh3.json` | Гидростатическая архитектура с более подробной сеткой |

Параметры первого опыта сохранены вместе с его тестами.
Его настройки остаются значениями по умолчанию при отсутствии `physical_policy`.
Варианты с `physical_policy` не наследуют отсечение 300 гПа и прежние вертикальные веса.
Смешение двух политик отклоняется с явной ошибкой до запуска обучения.
Входы первого опыта не фильтруются порогом целей; этот контракт не заменяется поведением второго опыта.

Исходный паспорт main сохранён как [PROFILE_R9_WEIGHTED](../PROFILE_R9_WEIGHTED.md).
Он содержит прежние обоснования; слияние само по себе их научно не подтверждает.
Обзор альтернативных вариантов находится в [PROFILE_R9](../PROFILE_R9.md).
Номер нового физического решения изменён на [0013](../decisions/0013-physical-profile-r9.md).
Существующее решение main [0012](../decisions/0012-weighted-loss-and-humidity-masking.md) сохранено.

## Техническое согласование

Сохранены обработка завершения процессов в `remote-research-runner.py` и новая конфигурация из main.
Фиксированные нормы, их хэши, исходные измерения и прошлые результаты не изменяются.
Сохранены проверки гидростатики, причинности, масок, градиентов, контрольных точек и прежнего варианта ошибки.
S1 использует начальный кадр без лишнего прогнозирования; повторный вызов после произвольного TypeError исключён.
Функция ошибки не меняется автоматически из-за внутреннего исключения.
Диагностика сохраняет политику опыта и отдельный счётчик исключённых порогом целевых записей q.

Предыдущие зелёные проверки не достаточны для этого согласованного дерева.
До переноса обязательны новые полные тесты, браузерные сценарии и прежние интеграционные проверки в CI.
Локальные формальные проверки не заменяют расчётные испытания.
Фактические номера запусков и итоговый SHA фиксируются в PR 10 после завершения проверок.

## Ограничения

Это интеграция экспериментального кода, не запуск удалённого обучения.
Рабочие службы, процессы и данные вычислительного узла не изменяются.
Смена исходников требует нового эксперимента либо проверяемой совместимой миграции; старые проверки продолжения не ослаблены.
R9 остаётся профильным пилотом без полного бюджета массы, воды и энергии.
Пошаговое сохранение C2 и физическая CUDA этой интеграцией не подтверждаются.
Прогностический выигрыш определяется будущим сравнением на общей целевой маске, а не успешным слиянием.
