# Обучение и исследовательский прогноз

## Назначение и ограничения

Версия 0.4 добавляет полный программный цикл для подготовленной выборки.
Цикл включает проверку данных, расчёт норм, обучение, продолжение, итоговый тест и прогноз по сохранённым весам.
Обучение не выполняет сетевые запросы.

Прикладная точность глобальной погоды пока не подтверждена.
Синтетический пример проверяет программу, а не заменяет метеорологический архив.
Физическая адаптация сохраняет устройство ядра 0.2.
Полный водный бюджет, пространственные кодировщики снимков и антенный оператор МТВЗА остаются отдельными задачами.

Используйте отдельный Python и CPU-сборку PyTorch.
Установите зависимости из README до работы с этими командами.
Для чтения NetCDF необходим набор `data`; для интерфейса необходим набор `lab`.

## Проверить полный цикл

Пути ниже предназначены для нового контрольного эксперимента.
Существующие выборки и каталоги экспериментов не перезаписываются.

1. Создайте аналитический синтетический набор.

```bash
python -m global_weather.pipeline demo-dataset --output outputs/example-data --horizon-hours 3
```

Команда создаёт пять примеров, маски, статические поля и нормы обучающей части.
Она не скачивает наблюдения и не использует выход нейросети как целевую истину.

2. Проверьте подготовленный набор.

```bash
python -m global_weather.pipeline validate --dataset outputs/example-data/dataset.json
```

Ожидаемый статус — `prepared_data_validated`.
Этот статус подтверждает программный контракт, а не независимую подлинность источника.

3. Выполните обучение.

```bash
python -m global_weather.pipeline train \
  --dataset outputs/example-data/dataset.json \
  --config configs/train_smoke.json --output outputs/example-training
```

Обучение изменяет веса по части `train`.
Часть `validation` выбирает лучшую эпоху.
Цели части `test` не читаются для обучения или выбора весов.

4. Выполните отдельный итоговый тест.

```bash
python -m global_weather.pipeline evaluate \
  --dataset outputs/example-data/dataset.json --run outputs/example-training \
  --split test --output outputs/example-test.json
```

Отчёт содержит ошибки по величине, уровню и сроку.
Контрольный прогноз сохраняет исходный анализ той же модели.
Для осадков такой контроль не рассчитывается.
Повторный подбор модели по результату итогового теста нарушает его независимость.

5. Рассчитайте прогноз по сохранённым весам.

```bash
python -m global_weather.pipeline forecast \
  --dataset outputs/example-data/dataset.json --run outputs/example-training \
  --sample sample-4 --horizon-hours 3 --output outputs/example-forecast
```

Прогноз не читает будущие цели, даже когда они присутствуют в манифесте.
Выход содержит физические величины, единицы, времена UTC и отдельные маски.
Сроки сохраняются последовательно; полный массив всех сроков не удерживается в памяти.

## Продолжить обучение

Создайте новую копию конфигурации и увеличьте только `epochs`.
Остальные параметры, исходники, версии численных библиотек и выборка должны совпадать.

```bash
python -m global_weather.pipeline train \
  --dataset outputs/example-data/dataset.json \
  --config /path/to/config-with-more-epochs.json \
  --output outputs/example-training --resume
```

Замените путь своим файлом конфигурации.
Исполнитель восстанавливает веса, оптимизатор и состояние генератора случайных чисел.
Завершённая эпоха хранится в отдельном каталоге `epochs/000001`.
Указатель `latest.json` изменяется только после записи файлов завершённой эпохи.

Если сохранённая эпоха неоднозначна после сбоя, остановите продолжение.
Не удаляйте её автоматически и не подменяйте указатель ради запуска.
Одновременное обучение в одном каталоге запрещено файловой блокировкой.
Ранняя остановка не снимается молчаливым продолжением.

## Подготовить реальные цели ERA5

Получите файлы через существующий коннектор CDS.
Сохраните исходные NetCDF и их происхождение.
Поддерживается прямоугольная географическая сетка с однозначными координатами, единицами, временем и давлением.

```bash
python -m global_weather.pipeline prepare-targets \
  --pressure-netcdf /path/to/pressure.nc --surface-netcdf /path/to/surface.nc \
  --issue-time 2020-01-01T00:00:00Z --mesh-level 3 \
  --horizon-hours 72 --step-hours 3 --confirm-utc \
  --precipitation-kind hourly_increment --output data/prepared/target-001.npz
```

Время и пути выше являются примером, а не сведениями о скачанном архиве.
Используйте `--confirm-utc` только после проверки временной оси.
Параметр `hourly_increment` означает количество осадков за час, который заканчивается меткой времени.
Для трёхчасовой цели нужны все три часовых значения.
Отсутствующий час делает сумму непригодной; он не заменяется нулём.
Метры водного эквивалента преобразуются в кг/м² множителем 1000.

Адаптер читает коэффициенты CF через xarray один раз.
Он выбирает только точные сроки и имеющиеся стандартные уровни.
Он не экстраполирует отсутствующие уровни, сроки или области.
Лишние измерения `expver` и ансамбля требуют отдельного согласования.

**Пространственный оператор — билинейная оценка в центре сферической ячейки.**
Он не является консервативным средним по площади ячейки.
Не используйте его как доказательство сохранения осадков или другого площадного интеграла.
Исходная детализация не повышается от более подробной сетки выдачи.

Ветер сначала переводится из локальных компонент в декартов касательный вектор.
После интерполяции вектор проецируется на восточное и северное направления целевой точки.
При отсутствии одной компоненты обе компоненты остаются непригодными.
Этот оператор не является консервативным переносом импульса.

Для статических полей используйте отдельный файл с поверхностным геопотенциалом и долей суши.

```bash
python -m global_weather.pipeline prepare-static \
  --netcdf /path/to/static.nc --mesh-level 3 --output data/prepared/static.npz
```

Рельеф вычисляется как поверхностный геопотенциал, делённый на 9,80665 м/с².
Это геопотенциальная высота поверхности в принятом приближении, не отдельная точная модель геометрических высот.
Файл с несколькими временными срезами статического поля требует предварительного выбора.
Температура моря, снег и лёд не подменяются постоянными полями.
Эти динамические состояния ещё не подключены к данному циклу.

## Собрать манифест

План имеет схему `global-weather-dataset-1` и тип `data_kind`: `real` или `synthetic`.
Он содержит `mesh_level`, `grid_fingerprint`, `pressure_hpa`, `step_hours`, `horizon_hours`, `registry`, `static`, `normalization`, `samples` и `license`.
Скопируйте отпечаток из подготовленной геометрии, не назначайте его произвольно.

У каждого примера нужны `id`, `split`, `issue_time`, `observations`, `targets` и `provenance`.
Части выборки: `train`, `validation`, `test`.
В `provenance` укажите происхождение наблюдений, целей, времени доступности и пространственный оператор.
Наблюдения имеют существующий скалярный контракт JSONL.
Пригодность спутниковых каналов проверяется до сборки набора.

В плане ссылки на файлы задаются относительными путями.
Команда `assemble` заменяет их объектами `path` и `sha256`.
Ссылки, выход за каталог и удалённые URL запрещены.
План и новый манифест должны находиться в одном каталоге.

```bash
python -m global_weather.pipeline assemble \
  --plan data/prepared/plan.json --output data/prepared/unscaled.json
```

Статус `manifest_sealed` означает фиксацию ссылок, а не допуск данных.
Если нормы ещё не рассчитаны, задайте `normalization: null`.
Рабочий манифест прогноза может иметь схему `global-weather-input-1` и часть `inference` без будущих целей.
Не используйте такой манифест для обучения.

## Рассчитать недостающие нормы

```bash
python -m global_weather.pipeline fit-norms \
  --dataset data/prepared/unscaled.json --output data/prepared/dataset.json \
  --base data/normalization/graphcast_base.json
```

Подготовьте базовый файл по руководству [нормализации](NORMALIZATION.md).
Параметр `--base` необязателен; без него все требуемые нормы рассчитываются по части `train`.
Глобальные нормы профилей используют анализ при нулевой заблаговременности и площади ячеек.
Для осадков используется первый полный интервал после каждого обучающего выпуска.
Спутниковые каналы используют отдельные уникальные наблюдения обучающей части.
Вес каждого такого наблюдения равен единице; это не площадная климатология спутникового покрытия.

Средние и дисперсии накапливаются в float64 без объединения всего архива в памяти.
Импортированные нормы сохраняют собственные хэши, период и условия использования.
Неизвестный период базовых норм не заменяется периодом собственного дополнения.
При неизвестном периоде независимая проверка временного разбиения блокируется.
Нулевая дисперсия или отсутствие данных также блокируют расчёт нормы.

## Формат целей

| Массив | Размер | Смысл |
|---|---|---|
| `profiles` | сроки × ячейки × 37 × 6 | T, q, u, v, геопотенциал, omega |
| `profile_mask` | как `profiles` | Пригодность каждой цели |
| `surface` | сроки × ячейки × 8 | T2, Td2, u10, v10, ps, MSLP, осадки, облачная доля |
| `surface_mask` | как `surface` | Пригодность приземных целей |

NPZ также содержит `lead_hours`, `pressure_hpa`, `issue_time`, `grid_fingerprint`, имена переменных и единицы.
Порядок и единицы заданы в `global_weather/vertical.py`.
Нулевая заблаговременность не содержит будущего накопления осадков.
Для профилей требуется пригодное целевое давление поверхности.
Отсутствующие уровни имеют маску false, а не стандартную атмосферу ISA.

## Запустить через интерфейс

Разместите готовый набор в `outputs/lab/datasets/ИМЯ/dataset.json`.
Откройте страницу `/training` работающего стенда.
Выберите проверку, обучение, итоговый тест или прогноз по весам.
Для двух последних действий выберите завершённое обучение из очереди.

Стенд ограничен 162 ячейками, 16 примерами и пятью эпохами.
Он использует прежние очередь, отмену, журнал, ограничения процессов и защиту запросов.
Интерфейс не принимает произвольные пути к весам или команды оболочки.
Поля и профили обученного прогноза доступны на основной сферической карте.
Источник synthetic остаётся явно обозначенным после обучения.

Для испытания до 72 часов используйте `scripts/pipeline-test.py`.
Для реального многосезонного исследования подготовьте отдельную конфигурацию и бюджет ресурсов.
`configs/train_72h.json` задаёт последовательное увеличение горизонта; он не является подтверждённым оптимальным рецептом.
Оценка памяти перед запуском является ограничителем, а не гарантией пикового потребления.
Многолетний архив, ускорители и распределённое обучение требуют отдельного масштабирования.
