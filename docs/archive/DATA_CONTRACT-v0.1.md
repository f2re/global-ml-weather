# Контракт наблюдений и целей

## Одна строка JSONL — одно скалярное измерение

```json
{"observation_id":"station-26063/2026-10-03T11:00:00Z/t2m","source":"station","variable":"t2m","value":281.2,"units":"K","latitude":59.97,"longitude":30.30,"elevation_m":6.0,"observed_at":"2026-10-03T11:00:00Z","available_at":"2026-10-03T11:08:00Z","revision":0,"valid":true,"quality":1.0}
```

Это пример структуры, не фактическое сообщение станции.

`available_at` включает декодирование и QC. Час из имени файла не доказывает
время его исторической доступности. Все времена содержат часовой пояс.
Допускаются только (t−12 ч,t] и available_at≤t. Исправления имеют стабильный ID
скалярного измерения и растущую revision. На одном уровне профиля разные
величины имеют разные ID; новое сообщение не должно случайно стереть другое.
Противоречащие друг другу одинаковые ревизии вызывают ошибку.

Источники: `station`, `radiosonde`, `electro_l`, `arktika_m`, `meteor_msu_mr`,
`meteor_mtvza`. Незнакомые источники и переменные не принимаются молча.

Отсутствующую величину можно не передавать или отметить valid=false.
Некорректное значение не аннулирует соседние скалярные измерения. `valid` —
настоящий JSON Boolean, не строка "false". `quality` лежит в (0,1], имеет
описанный upstream смысл; это не уверенность прогноза. Нулевое значение не
является признаком отсутствия. Учитывается время конкретного уровня радиозонда.

Аэрология дополнительно содержит `pressure_pa`. Число уровней произвольное;
распределение на соседние уровни идёт по log(p). Измерения за пределами
поддерживаемого диапазона не экстраполируются. Высота станции не подставляется
незаметно вместо неизвестной траектории радиозонда. Референсный адаптер использует
координаты, переданные в каждой строке.

## Реестр величин и каналов

Сохраняется JSON-словарь `имя → units,offset,scale,vertical`. Для спутниковых
переменных обязательны `source`, `platform`, `channel_id`; они входят в
контрольный отпечаток схемы. Модель не должна продолжать работать с другими
единицами, нормировками или переставленными каналами.

```json
{
  "t2m": {"units":"K","offset":273.15,"scale":30,"vertical":"surface"},
  "SYNTHETIC_IR": {
    "units":"K","offset":250,"scale":50,"vertical":"column",
    "source":"electro_l","platform":"SYNTHETIC","channel_id":"example_only"
  }
}
```

Второй элемент — исключительно пример описания, не таблица каналов МСУ-ГС.
Реальный реестр составляется по документации конкретного прибора и проверенному
экспорту. Значения offset/scale из кода — инженерные стартовые масштабы;
они не рассчитаны по метеорологическому датасету.

## Дополнительные требования к спутнику

Строка содержит `platform`, `channel_id`, `footprint_km` (диаметр/характерный
размер пятна в согласованной upstream трактовке), `view_zenith_deg` и объект
`radiometry`:

```json
{"instrument":"VERIFIED_INSTRUMENT_ID","quantity":"brightness_temperature","units":"K","physical_channel_ids":["VERIFIED_CHANNEL_ID"],"calibration_id":"VERSION_AND_PROVENANCE","channel_mapping_verified":true}
```

Разрешены физические яркостные температуры, отражательные характеристики и
спектральные радиансы с единицами из `RadiometrySpec`. `raw_counts` не принимаются
как кельвины. Для отражения требуется `solar_zenith_deg<90`. Числовой диапазон и
флаги качества проверяются до этого контракта; сам контракт не калибрует прибор.

Пятно, превышающее sqrt(площади ячейки), получает отказ
`footprint_operator_required`. Даже принятое компактное пятно в 0.1 представлено
центром, а не точным интегралом антенны; такое приближение надо отдельно проверять.
Анизотропия пятна, перекрытие ячеек, параллакс облаков, реальные спектральные
функции и согласование приборов относятся к следующему адаптеру.

Число физических каналов не зашито. Нет предположения, что `hrpt30` эквивалентен
30 подтверждённым микроволновым каналам. PNG/RGB и product.cbor сами по себе не
доказывают пригодность данных. Все исходные файлы, контрольные суммы, калибровки
и версии обработки должны сохраняться вне обучающего тензора.

## Формат подготовленных целей

`training.Targets` содержит lead_hours, profiles[K,N,37,6],
profile_mask[K,N,37,6], surface[K,N,8], surface_mask[K,N,8], давления и
отпечаток сетки. Порядок и единицы перечислены в `vertical.py`.

Каждое значение с маской true должно быть конечным. Нижние уровни маскируются
по независимым данным о поверхности; при наличии целевого ps проверка явная.
У анализа lead=0 нет будущего интервала накопления осадков. Для lead=3 при
шаге 3 ч цель — сумма осадков за (t,t+3 ч], для lead=6 — за (t+3,t+6 ч].
Шестичасовая сумма не делится на два произвольных трёхчасовых наблюдения.

Интерполяция реанализа на мелкую сетку не делает его истинными мелкомасштабными
целями. Для физического поля требуется согласованный оператор усреднения/
переноса, а для станций — оператор сравнения в координатах станции. Они ещё
не реализованы как готовый конвейер подготовки целей.

## Что экспортируется в демонстрации

Четыре смысловых маски разделены. `observation_mask[N,6]` и
`input_age_at_issue_hours[N,6]` описывают прямое покрытие источниками **при
выпуске**, не покрытие в будущем и не погрешность. Бесконечный возраст означает
отсутствие источника. `profile_mask[K,N,37]` исключает подземные уровни и
область вне запроса. `surface_mask[K,N,8]` дополнительно исключает осадки lead=0.
Маски обучающих целей передаются отдельно и не берутся из прогноза.
