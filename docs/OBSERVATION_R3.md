# Запуск станционного опыта R3

Применяйте [решение 0006](decisions/0006-station-native-pilot.md) и [контракт наблюдений](../agents/OBSERVATION_TRAINING_CONTRACT.md).

Код запуска: `scripts/remote-observation-runner.py`.
Служба: `scripts/global-weather-r3.service.in`.
Конфигурация обучения: `configs/observation_r3_training.json`.
Рабочая копия узла: `/home/user/global-ml-weather-r3`.

Служба проверяет точный SHA и чистоту исходников.
Затем она выполняет обязательные программные проверки, допускает станции по train, загружает 2022 год, готовит выборку и обучает новые веса.
Итоговый станционный test запускается отдельной командой после выбора лучшей эпохи.
Обучающий модуль не получает пути ERA5 и не открывает её файлы.

Исходный кэш 2021 года читается из остановленного R2 без изменения файлов.
Новый кэш хранится в `outputs/remote-r3-stations/cache`.
Загрузка ограничена 16 ГиБ; каталог нового опыта ограничен 96 ГиБ.
Минимальный свободный остаток диска составляет 64 ГиБ.
Служба ограничивает RAM до 96 ГиБ, CPU до восьми ядер и срок до 14 суток.

`Linger=yes` сохраняет пользовательскую службу после разрыва SSH и выхода из сеанса.
Служба имеет не более трёх попыток и абсолютный срок остановки.
Управление процессами принадлежит systemd; SSH используется для передачи ревизии и проверки статуса.

Каждая завершённая эпоха получает отдельный каталог с весами, оптимизатором, RNG и показателями.
Продолжение требует прежних данных, норм, конфигурации, исходников и численной среды.
Неоднозначная эпоха после прерывания сохраняется и блокирует автоматическое продолжение.

## Проверка статуса

```bash
systemctl --user status global-weather-r3.service
journalctl --user -u global-weather-r3.service --no-pager -n 30
cat ~/global-ml-weather-r3/outputs/remote-r3-execution/evidence.json
```

Журнал различает программные проверки, загрузку, подготовку, обучение и test.
Успешный запуск службы не означает завершения обучения.
Приёмка профильной модели и проверка ERA5 остаются отдельными незавершёнными этапами.
