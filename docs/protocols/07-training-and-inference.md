# Протокол 07. Обучение и исследовательский прогноз

## До обучения

Для новых реальных опытов применяйте [GLOBAL-WEATHER-OBS-1](../../agents/OBSERVATION_TRAINING_CONTRACT.md).
Обучайте по фактическим измерениям; ERA5 используйте только для отдельной проверки замороженной модели.

Применяйте `GLOBAL-WEATHER-OPS-1` и [контракт цикла](../../agents/PIPELINE_CONTRACT.md).
Прочитайте [руководство](../TRAINING.md).
Зафиксируйте тип данных, манифест, исходники, нормы, конфигурацию и пространственный оператор.

Разделите примеры хронологически.
Между частями не должны пересекаться 12-часовые входы и будущие цели.
Учитывайте весь заявленный горизонт набора, а не только короткий первый этап обучения.
Для пяти профильных величин R7 используйте фиксированные нормы GraphCast по [решению 0010](../decisions/0010-graphcast-fixed-normalization.md).
Нормы остальных каналов рассчитывайте только по `train`.
R8 добавляет фиксированный климатический контекст по [решению 0011](../decisions/0011-seasonal-climate-context.md).
Его хэш входит в происхождение новой архитектуры; веса R7 автоматически не переносятся.
Прогноз может читать известный календарь, но не будущие фактические поля.
Сохраните неизвестный период импортированных норм как неизвестный.

Проверьте наличие целевого ps для каждой колонки с профилями.
Не используйте прогнозируемое ps, чтобы исключить трудные цели.
Нулевая заблаговременность не задаёт будущие осадки.
Неполный интервал накопления не дополняется нулями.

## Исполнение

Используйте фиксированный модуль `global_weather.pipeline`.
Запретите сетевые операции, произвольные импорты и команды из манифеста.
Соблюдайте лимиты памяти, процессов и файлов.
При изменении манифеста, норм, схемы или исходных массивов остановите эксперимент.

Выбирайте лучшую эпоху только по `validation`.
При постепенном увеличении обучающего горизонта сохраняйте постоянный горизонт проверки.
Не читайте цели `test` при обучении и выборе весов.
Не изменяйте гиперпараметры по итоговому тесту, сохраняя прежнее заявление о его независимости.

Каждая завершённая эпоха имеет собственные файлы и хэши.
Продолжение восстанавливает веса, оптимизатор и генератор случайных чисел.
Оно требует прежних данных, исходников и численной среды.
Не перезаписывайте неоднозначную эпоху после сбоя.

## Оценка и выдача

Выполните итоговый тест отдельной командой.
Сохраните MAE, RMSE и смещение по величинам, уровням и срокам.
Для сравнения используйте те же цели и площади ячеек.
Сохранение начального анализа не является независимой численной моделью погоды.

Прогнозный режим не должен читать будущие цели.
Проверьте это тестом, который запрещает вызов загрузчика целей.
Допускайте отдельный входной манифест без целевых файлов.
Сохраняйте единицы, срок, маски, происхождение весов и норм в результате.

Синтетический источник остаётся синтетическим после обучения.
Статус `trained_research` не даёт оперативного допуска.
Численные ошибки на ERA5 не заменяют проверку независимыми наблюдениями.
Оператор билинейного переноса в центр не подтверждает сохранение площадных интегралов.

## Приёмка программного этапа

```bash
python -m pytest tests/test_pipeline.py -q
python scripts/pipeline-test.py
python scripts/pipeline-browser-test.py
```

Дополнительно выполните полный набор тестов, прежний браузерный сценарий и проверку документации.
Пропуск, таймаут или неполный отчёт не считаются успешным испытанием.
Фиксируйте фактический коммит, а не предыдущую зелёную проверку.
