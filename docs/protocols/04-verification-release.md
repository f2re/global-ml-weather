# Протокол 04. Верификация и выпуск

## Разделить доказательства

| Этап | Что проверяется |
|---|---|
| A | Контракт и единицы |
| B | Аналитические физические случаи |
| C | Синтетическое исполнение и градиенты |
| D | Реальные обучающие данные |
| E | Независимая точность прогноза |
| F | Работа с оперативными задержками |

Прохождение одного этапа не подтверждает следующий.
Успешный синтетический расчёт не подтверждает качество погоды.

## Подготовить независимую выборку

Разделите архив хронологически по погодным эпизодам.
Входные и целевые окна разных частей не должны пересекаться.
Учитывайте годы предварительного обучения, период норм и исправления архива.
Не подбирайте параметры по окончательному тесту.
Не скрывайте ошибки прогнозным давлением в маске.

Используйте реальные площади сферических ячеек.
Не умножайте их повторно на `cos(latitude)`.

## Проверить прогноз

Оцените +24, +48 и +72 часа отдельно.
Разделите результаты по величинам, уровням, сезонам, Арктике и покрытию.
Проверьте инверсии, тропопаузу и вертикальный сдвиг ветра.
Для осадков разделите событие, количество, интервал и пространственный масштаб.
Для ансамбля проверьте калибровку и согласованность полей.

Сравните сохранение состояния, интерполяцию и доступный контрольный прогноз.
Согласуйте фактическую доступность входов.
Исключайте источники отдельно и группами.
Сравните граф, HEALPix и `K=4/8/16/38` при согласованных данных и ресурсах.
Нереализованный вариант не называйте выполненным экспериментом.

`paired_scores` рассчитывает MAE, RMSE и смещение.
Контрольный прогноз сравнивается по тем же целям.
Без цели метрика отсутствует, а не равна нулю.
Входы должны иметь единицы, SHA256 и источник.
Сам расчёт не удостоверяет независимость данных.
Гидростатический остаток является диагностикой, а не точностью погоды.

## Сохранить запуск

Запишите ID, UTC, параметры, зерно, нормы, схему и исходный коммит.
Сохраните хэши файлов, версии пакетов, устройство, время, память, вывод и код возврата.
Сохраните результаты с контрольными суммами.
Неполный запуск не помечайте успешным.

## Принять инженерную публикацию

1. Выполните весь набор `pytest`.
2. Выполните исходный и адаптивный расчёты до +72 часов.
3. Выполните проверки коннекторов с необходимыми зависимостями.
4. Выполните обязательный браузерный сценарий.
5. Проверьте документацию командой `python scripts/check_docs.py --strict`.
6. Сверьте публикуемые файлы с испытанными.
7. Проверьте итоговый SHA и его задания CI.
8. Повторно проверьте HEAD основной ветки перед прямым продвижением.

Отчёт должен разделять локальные проверки и GitHub Actions.
Рецензент проверяет фактические артефакты. Одобрение не присваивается автоматически.
Инженерный коммит не является научным допуском оперативного прогноза.
