# Протокол 04. Верификация и выпуск

Ступени доказательств не взаимозаменяемы:
A. Контракт и единицы → B. Аналитические физические тесты → C. Синтетическое
исполнение/градиенты → D. Реальные обучающие данные → E. Независимое качество
прогноза → F. Испытание с оперативными задержками. Прохождение C не означает E.

Разбить архив хронологически по погодным эпизодам. Входные/целевые окна разных
частей не пересекаются. Учитывать историю предобучения, период норм и исправления
архива. Не подбирать гиперпараметры по финальному тесту. Не маскировать плохие
предсказания их собственным ps. Ошибка по площади использует действительные
площади сферических ячеек, а не дополнительный cos(latitude) поверх них.

Верификация отдельно по +24/+48/+72 ч, переменным, уровням, сезонам, Арктике,
покрытию. Профили: инверсии, тропопауза, сдвиг ветра. Осадки: событие/количество,
интервал, пространственные масштабы; ансамбль: калибровка и согласованность.
Контрольные методы: сохранение состояния, интерполяция, фоновый прогноз при
сопоставимой фактической доступности. Источники исключать по одному и группами.
Сравнить граф/HEALPix и K=4/8/16/38 при согласованных данных и ресурсах.

paired_scores даёт MAE/RMSE/смещение, опционально относительное улучшение RMSE
к контрольному прогнозу по тем же целям. Нет цели — нет метрики, а не ошибка 0.
Входные массивы имеют явные единицы, SHA256 и источник. Расчёт метрики сам по
себе не удостоверяет независимость данных. Гидростатический остаток — диагностика,
не точность погоды. Отдельно сохранять нарушения физических границ.

Каждый запуск: ID, UTC, параметры, seed, нормировка, схема, исходный commit и
хэши файлов, версии пакетов, устройство, время, память, stdout, код возврата,
выходы с контрольными суммами. Неполный запуск не выдавать за успешный.

Перед публикацией: pytest; baseline/adaptive до +72 ч; тесты коннекторов без
сети; браузерное прохождение запуска, профиля, таймлайна, ошибок и отмены;
упаковка статических ресурсов; сравнение опубликованных blob SHA с проверенными.
Отчёт разделяет локальные и GitHub Actions проверки. Результат чужого агента
проверяется рецензентом; отметка «одобрено» не присваивается автоматически.
