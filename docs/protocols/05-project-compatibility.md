# Протокол 05. Совместимость с проектами-поставщиками

Обязателен для разработчика, исполнителя, верификатора и аудитора выпуска.
Действует вместе с протоколами 01–04 и решением 0002. Изменение требований
допускается только отдельным явно утверждённым архитектурным решением.

## Проверенные ревизии и граница доказательств

`configs/upstream_contracts.json` закрепляет `f2re/arktika-worker` main
4d744570653ac60c8fd059d10e617c3806a6bafc и `f2re/SatDump` release/1.2.2
394431e11d9fffe1a73d3e0670fb023ad7562241. Это ревизии проверенного ИСХОДНОГО
кода, не доказательство версии установленной программы или физических файлов.
Файлы контрактов проверяются по Git blob SHA1; данные — отдельно по SHA256.

Уровни результата:
1. Исходный контракт проверен: структуры соответствуют закреплённому коду.
2. Программная интеграция проверена на синтетических файлах этой структуры.
3. Реальный архив проверен: нужны фактические файлы оператора, их происхождение,
   временные журналы и самостоятельный радиометрический/геометрический контроль.
4. Качество прогноза проверено: нужны веса, независимые цели, контрольные методы.

Первые два пункта НЕ означают последние два. Метка `training_ready=false`
не снимается из-за наличия `product.cbor`, успешной загрузки или красивой карты.

## До исполнения

Прочитать корневой AGENTS.md, agents/AGENTS.md, собственный файл роли, решение
0002 и ВСЕ протоколы. Проверить рабочую копию модели, точные ревизии поставщиков,
чистоту исходников и размерности. Не импортировать upstream Store: конструктор
меняет состояния очереди. Использовать read-only мост.

```bash
python -m global_weather.connectors.preflight \
  --project-root . --arktika-source /path/to/arktika-worker \
  --satdump-source /path/to/SatDump --report outputs/check-001/preflight.json
```

Код 2, `not_checked`, расхождение хэшей/ревизии, грязная рабочая копия,
отсутствие агентского файла — STOP для заявления о совместимости. Не подменять
ожидаемые хэши актуальными без повторного аудита. Источники не скачиваются и
не перестраиваются этой командой. Отчёт не пишется в каталоги поставщиков.

## Правила приёма

Арктика: каталог SQLite читается только через `mode=ro`, согласованным снимком
assets/jobs. Не читать settings/ключи и не писать в БД. Учитывать завершённость
job и `.download.json`: asset_id, size, SHA256, time. `time` журнала — готовность
загрузки, не время измерения и не готовность последующей физической обработки.
`time_assumed=true`, незавершённые файлы и несовпадающие хэши блокируют допуск.
Подписанные URL не копировать в общедоступный отчёт.

В проверенной версии normalize_item разрешает только ARCM1/ARCM2. Наличие
`electrol2_srf.json` не доказывает загрузчик «Электро-Л». Для «Электро-Л»
поддерживается отдельный путь SatDump/msu_gs и проверенный физический экспорт.

SatDump: читать dataset.json и product.cbor, сохранять имена и порядок каналов,
времена строк/изображений, projection_cfg, needs_correlation, матрицу и статусы.
Декодирование CBOR не исполняет код калибровки. Имеющаяся конфигурация калибратора
не означает, что сохранённые PNG/TIFF уже содержат K. `hrpt30` — транспортная
раскладка, не утверждение числа физических каналов. `no_data` не заменять нулями.
Голые MSU-GS-*.png из сырого модуля без метаданных не допускаются автоматически.
Не выводить наблюдение, платформу и время готовности из имени файла/mtime.

Физический мост принимает ограниченный одноканальный GeoTIFF и независимую
попиксельную геометрию. Нужны проверенная связь с native metadata и ревизией,
reference к калибровке/геометрии/времени/QC, явные scale/offset/единицы и журнал.
`assumed`, DN=K, RGB, несогласованные CRS или каналы — STOP. Видимые каналы 1–3
МСУ-ГС не являются тепловыми. МТВЗА остаётся заблокированным для точечного
экспорта до реализации антенного оператора. Это физическое ограничение, не
«ошибка чтения файла», которую разрешено обходить.

## Причинность, нормализация и научная концепция

История (t−12ч,t]; available_at≤t; время измерения≤готовности. Временная
метка каждого пикселя сохраняется; пролёт не размножается по почасовым срокам.
Стабильный ID съёмки/сетки + канал + исходная координата пикселя и ревизия
сохраняются для исключения повторного усвоения. Перевыпуск тайла не должен
превращать те же измерения в «новые независимые».

Данные остаются физическими до z-нормализации. Нормы фиксированы по реанализу/
обучающим наблюдениям с происхождением; спутниковым каналам нужны собственные
нормы. Недостающие измерения не заполняются реанализом или климатологией.
Маски наблюдений, целей, подземных уровней и выдачи независимы. Не обрезать
глобальную динамику; выдавать все 37 изобар и прогноз до 72ч согласно концепции.
Адаптация активаций по физическому состоянию не равна полной консервативной
динамике. Сохранение энергии/влаги не объявляется по одному потоковому тесту.

## После изменения

Выполнить общий pytest, специальные tests/test_project_bridge.py, оба варианта
расчётного ядра и Chromium-сценарий. Обязательные проверки не должны быть skipped;
установить совместимые зависимости в отдельное окружение, не системный Python.
Проверить отсутствие записи upstream, символических ссылок и переходов `..`.
Реальный архив проверять отдельно; тестовые фикстуры явно маркировать synthetic.

## Отчёт и разрешение выпуска

Нужны: задача, ревизии, Git tree/хэши, команды, окружение, UTC начала/конца,
коды возврата, файлы результатов, негативные тесты, неиспытанные режимы, решение.
Данные и бинарная версия оператора неизвестны — это написать явно. Не утверждать
независимую работу агента без фактического вызова/отчёта. Автор реализации не
приписывает себе одобрение другой роли. Аудитор допускает программный выпуск
отдельно от метеорологической эксплуатации. Слияние только по поручению оператора,
после проверки текущего main, без force-push и без потери параллельных изменений.
