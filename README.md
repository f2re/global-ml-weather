# global-ml-weather

Глобальная исследовательская модель погоды. Версия 0.5.0.

Модель использует разреженные атмосферные наблюдения за 12 часов и рассчитывает прогноз до 72 часов.
Выход содержит 37 изобарических уровней от 1000 до 1 гПа и приземные величины.
Внутренняя сетка охватывает Землю; маска выдачи не обрезает глобальную динамику.

**В репозитории нет весов с подтверждённой метеорологической точностью.**
Синтетические примеры проверяют программу, а не качество погоды.
Численный оператор продукции не удостоверяет физическую готовность конкретного файла SatDump.

## Что работает

Адаптивное ядро использует направленный граф, физические признаки состояния и сжатую вертикаль.
По умолчанию колонка содержит восемь скрытых позиций.
Геометрия — двойственная икосаэдрическая сетка с 12 пятиугольниками, не H3.
Станции и аэрологические профили могут быть неполными.

Подготовленная выборка проходит проверку времён, единиц, масок, уровней и контрольных сумм.
Нормы фиксируются по обучающей части либо импортируются с сохранением происхождения.
Обучение сохраняет каждую эпоху, оптимизатор и состояние генератора случайных чисел.
Итоговый тест выполняется отдельно от выбора весов.
Прогноз по сохранённым весам не читает будущие цели.

Версия 0.5 добавляет условные методы спутниковой продукции и её приём в модель.
Поверхностные и облачные продукты имеют собственные идентификаторы, нормы, ограничения возраста и происхождение.
Они уточняют начальное состояние, но не заменяют исходные каналы.

Стенд показывает очередь, журналы, поля на сфере, вертикальные профили и диагностики.
Страница `/training` добавляет проверку выборки, обучение, итоговый тест и прогноз по весам.
Оба интерфейса используют одну очередь и одного исполнителя.

## Установить

Требования: Linux, отдельный Python 3.10+ и CPU-сборка PyTorch.
Не заменяйте системный Python Astra. Docker и Node.js для работы не нужны.
Сетевая установка требует разрешения оператора.

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install 'torch>=2.2,<3' --index-url https://download.pytorch.org/whl/cpu
python -m pip install -e '.[test,data,lab,ecosystem]'
python -m pytest -q
```

Для GeoTIFF нужен `rasterio`; для NetCDF нужны зависимости `data`.
Установщик `scripts/install-lab.sh` сохраняется как отдельный вариант.
Его режим `--offline` требует заранее подготовленного совместимого каталога пакетов.
Готовый комплект всех зависимостей в репозиторий не включён.

## Рассчитать спутниковую продукцию

| Продукт | Реализованный метод | Необходимое условие |
|---|---|---|
| NDVI, NDVI TOA | Отношение красной и ближней ИК-полос | Проверенные отражения, дневное освещение и маска |
| NDMI, NDSI | Отношение соответствующих полос | Нужна полоса около 1,6 мкм; у МСУ-ГС её нет |
| Влажность почвы | Условная инверсия τ–ω по H/V | Калибровка, атмосферная коррекция и приборная таблица |
| Облачная яркостная температура | Отбор теплового канала по маске | Не считается термодинамической температурой облака |
| Высота верхней границы | Однозначное пересечение температуры с профилем | Скорректированная температура и непрозрачное однослойное облако |
| Водозапас жидкой воды | Формула по оптической толщине и радиусу | Эти параметры должны быть восстановлены заранее |
| Температура поверхности | Монохроматическая радиационная инверсия | Излучательная способность и атмосферные члены заданы |

Все методы имеют отдельные маски и причины отказа.
Никакой индекс не переименовывается во влажность почвы.
Ни один метод не получает вымышленные приборные коэффициенты.

```bash
python -m global_weather.products catalog
python -m global_weather.products calculate --job data/job.json --output data/product.npz
python -m global_weather.products export --product data/product.npz --geometry data/geometry.npz --output data/products.jsonl --registry-output data/product-registry.json
```

Подготовьте задание и физические входы по [руководству продукции](docs/SATELLITE_PRODUCTS.md).
Примеры путей не означают наличие соответствующих данных в репозитории.
Расчёт продукции выполняется через CLI; отдельная страница расчёта продуктов пока не добавлена.

Добавьте экспортированные записи и реестр в новую подготовленную выборку.
Пересоберите манифест и нормы, затем обучите модель с этими входами.
Старые веса не получают новые признаки автоматически.
Для медленного контекста поверхности допускается отдельный возраст без изменения времени измерения.
Границы частей выборки учитывают это окно.

## Проверить обучение

Используйте новые каталоги. Команды не перезаписывают существующий эксперимент.

```bash
python -m global_weather.pipeline demo-dataset --output outputs/example-data --horizon-hours 3
python -m global_weather.pipeline validate --dataset outputs/example-data/dataset.json
python -m global_weather.pipeline train --dataset outputs/example-data/dataset.json --config configs/train_smoke.json --output outputs/example-training
python -m global_weather.pipeline evaluate --dataset outputs/example-data/dataset.json --run outputs/example-training --output outputs/example-test.json
python -m global_weather.pipeline forecast --dataset outputs/example-data/dataset.json --run outputs/example-training --sample sample-4 --horizon-hours 3 --output outputs/example-forecast
```

Первый шаг создаёт аналитические данные с явной меткой `synthetic`.
Цели не получаются из выхода необученной сети.
Для проверки всего горизонта выполните `python scripts/pipeline-test.py`.
Подготовка реальной выборки и продолжение обучения описаны в [руководстве](docs/TRAINING.md).

## Открыть интерфейс

```bash
python -m global_weather.pipeline demo-dataset --output outputs/lab/datasets/demo --horizon-hours 3
python -m global_weather.lab.app --workspace outputs/lab --port 8765
```

Откройте `http://127.0.0.1:8765/training` для работы с выборкой.
Основная страница `http://127.0.0.1:8765` показывает поля и профили.
На странице обучения выберите набор, действие и завершённое обучение для оценки или прогноза.

Не публикуйте стенд в интернет без отдельной системы доступа.
Он работает на локальном адресе и не предоставляет произвольный запуск Python или оболочки.
Предел обучения в интерфейсе: 162 ячейки, 16 примеров, пять эпох.
Для более крупного исследования используйте CLI и отдельный бюджет ресурсов.

## Подключить существующие проекты

| Источник | Реализованный вход | Ограничение |
|---|---|---|
| `arktika-worker` | `product.json`, `values.tif`, `quality.tif` | Численные ИК-каналы 4–10 без повторной шкалы |
| GPTL | Локальный L2IR, метаданные и `.download.json` | Нужны подтверждённые канал, время и геометрия |
| SatDump `release/1.2.2` | `dataset.json`, `product.cbor`, каналы | Контейнер не подтверждает радиометрию |
| Станции и аэрология | Физические сообщения JSONL | Пропуски и время доступности сохраняются |
| ERA5 | Локальный CF-NetCDF | Цели и нормы, не замена отсутствующих наблюдений |

Ревизии поставщиков закреплены в `configs/ecosystem_sources.json`.
Их проверка не удостоверяет установленный бинарный файл SatDump.
МТВЗА по-прежнему требует физической калибровки, таблицы каналов и антенного оператора.
Каталоги, журналы и службы поставщиков не изменяются.

```bash
python -m global_weather.compatibility satdump /path/to/output/dataset.json --require msu_mr mtvza
```

Замените пример пути своим каталогом.
Порядок допуска описан в [совместимости проектов](docs/ECOSYSTEM.md).
Общий каталог источников описан в [коннекторах](docs/CONNECTORS.md).
Мост `products from-capsule` использует готовые численные капсулы Арктики и «Электро-Л» без повторной калибровки.

## Подготовить нормы

Базовый источник — опубликованные статистики ERA5 семейства GraphCast.
Это средние и стандартные отклонения по уровням, не веса чужой сети и не локальная сезонная климатология.

```bash
python -m global_weather.import_climatology --download data/normalization/upstream --output data/normalization/graphcast_base.json
```

Загрузка является отдельной сетевой операцией.
Во время обучения и прогноза используются локальные файлы.
Численные файлы исходных норм не включены в эту публикацию.
Период расчёта базовых норм необходимо подтвердить.

Модуль `fit-norms` дополняет базовый набор статистиками своей обучающей части.
Для Td2, ps, облачности, трёхчасовых осадков, спутниковых каналов и продукции нужны соответствующие нормы.
Не заменяйте их инженерными коэффициентами.
Неизвестный период импортированной компоненты блокирует заявление о независимом временном тесте.
Подробности: [нормализация](docs/NORMALIZATION.md) и [обучение](docs/TRAINING.md).

## Использовать агентов

Девять ролей имеют инструкции в `agents/` и определения в `.claude/agents/`.
Применяйте `GLOBAL-WEATHER-OPS-1`, `GLOBAL-WEATHER-TRAIN-1` и `GLOBAL-WEATHER-PRODUCTS-1` в соответствующих задачах.
Все протоколы перечислены в [общем указателе](docs/protocols/README.md).
Документация использует русский профиль `RU-TECH-1`.

```bash
python -m global_weather.lab.agents
python -m global_weather.lab.agents --role executor --action train_dataset --dataset-id demo --horizon-hours 3 --epochs 1 --workspace outputs/agent-lab --execute
```

Перед второй командой установите набор в каталог `outputs/agent-lab/datasets/demo`.
Не используйте каталог одновременно с другим исполнителем.
Это диспетчер разрешённых действий, а не автономная группа языковых моделей.
Инструкции не заменяют изоляцию ОС или независимую рецензию.

## Проверки и ограничения

```bash
python -m pytest -q
python scripts/products-test.py
python scripts/pipeline-test.py
python scripts/check_docs.py --strict
```

Браузерные проверки требуют Playwright и установленного Chromium.
Выполните `scripts/browser-test.py` и `scripts/pipeline-browser-test.py` после изменения интерфейса.
Сравнивайте результаты для итогового коммита.

Не приравнивайте билинейное значение в центре ячейки к консервативному среднему по площади.
Пространственные кодировщики снимков, динамика почвы, SST, снег, лёд и полный водный бюджет ещё требуют реализации.
Условная инверсия почвы не создаёт отсутствующую калибровку МТВЗА.
Формула LWP не восстанавливает автоматически оптическую толщину и радиус капель.
Многосезонное обучение и научная проверка по реальным наблюдениям не проведены в рамках этой публикации.
