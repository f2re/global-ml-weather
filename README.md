# global-ml-weather

Глобальная исследовательская модель: наблюдения за 12 часов → состояние
атмосферы → прогноз до 72 часов. Источники: разреженные станции и аэрология,
«Электро-Л», «Арктика-М», «Метеор-М» МСУ-МР/МТВЗА. Геометрия — двойственная
икосаэдрическая сетка, преимущественно гексагоны и 12 пятиугольников, не H3.

**Версия 0.3.0. Обученных метеорологических весов и подтверждённой точности нет.**
Есть физически обусловленное ядро и локальный стенд; синтетические результаты
не являются прогнозом погоды.

## Интерфейс испытаний

```bash
# В существующей среде Python 3.10+ с CPU-версией PyTorch:
python -m pip install -e '.[test,data,lab]'
python -m global_weather.lab.app --workspace outputs/lab --port 8765
```

Открыть http://127.0.0.1:8765. Docker, Node.js, CDN и внешние карты не нужны.
Установщик: `bash scripts/install-lab.sh`; режим `--offline` требует заранее
собранного совместимого WHEELHOUSE. Это не готовый офлайн-пакет зависимостей.

Стенд запускает исходный/адаптивный граф на 12–642 ячейках, до +72 ч, с выбором
D/K, зерна, исключения источников и синтетической проверки оптимизатора.
Есть очередь, отмена, таймаут, протокол и история. Результат: вращаемая сфера,
выбор поля/изобары/срока/ячейки, вертикальный профиль, физические диагностики.
Независимые цели отсутствуют — качество погоды не измерено, RMSE не выдумывается.

Вкладки: испытания, источники данных, агенты разработки и протоколы. Файлы
поступают в локальный входной каталог без перезаписи; инспекция структуры
не объявляется проверкой калибровки. Сеть из веб-интерфейса не запускается.
Подробнее: [LAB.md](docs/LAB.md).

## Модель 0.2 сохраняется

`AdaptiveWeatherModel`: совместное кодирование значения и канала; направленные
графовые сообщения с геометрией и физическими признаками; 8 скрытых позиций
колонки и выход на все 37 изобар 1000–1 гПа; собственный фоновый анализ и
защита от повторного усвоения. Адаптация означает изменение активаций по
состоянию, а не онлайн-переобучение или автоматическое сгущение сетки.

Фиксированные z-нормы реанализа используются согласованно для входов, выхода
и ошибки. Базовый источник GraphCast/ERA5 закреплён в
`configs/normalization_sources.json`. Нужны реальные проверенные файлы и
недостающие нормы Td2, ps, облачности, 3-часовых осадков и спутниковых каналов.
Климатическая норма не заменяет отсутствующее наблюдение. Инженерные масштабы
допустимы только в явно синтетических проверках.

Гидростатическая дополнительная ошибка и отдельный консервативный оператор
обмена есть; полный водный/энергетический бюджет, HEALPix-конкурент, спутниковые
пространственные кодировщики и антенный оператор пока не реализованы.
[Принятые решения](docs/decisions/0002-physically-adaptive.md).

## Коннекторы и агенты

[Коннекторы](docs/CONNECTORS.md): JSONL, инвентаризация SatDump, GraphCast,
NOAA ISD CSV, ERA5 CDS, локальный манифест Электро/Арктика. Сетевая загрузка
только отдельной командой с --network; исходники и хэши сохраняются.
Геопортальный API и полная радиометрическая обработка не объявляются готовыми.

[Девять ролей](agents/README.md): координатор, данные, радиометрия, нормализация,
физика, модель, исполнение, верификация и аудит выпуска. Универсальные инструкции
в agents/, определения Claude Code в .claude/agents/. Автономные LLM не запускаются.

```bash
python -m global_weather.lab.agents
python -m global_weather.lab.agents --role executor --action adaptive --execute
python -m global_weather.connectors.acquire era5-request \
  --date 2020-01-01 --output data/era5-request.json
```


нужны явно сопоставленные прогноз/цели, маски, площади и манифест с SHA256.

Стенд привязан только к loopback. Не публикуйте его в интернет без отдельной
аутентификации и защиты. Инструкции агентов не являются ОС-песочницей.
