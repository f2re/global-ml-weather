# global-ml-weather

Исследовательская модель «наблюдения за 12 часов → глобальное состояние →
прогноз до 72 часов». Входы: разреженные станции и аэрология, «Электро-Л»,
«Арктика-М», проходы «Метеора-М» МСУ-МР и МТВЗА. Геометрия — двойственная
икосаэдрическая сетка с 12 пятиугольниками, не H3.

**Версия 0.2.0: исполняемые исследовательские компоненты. Обученных весов,
подтверждённого качества и готового оперативного прогноза нет.**

## Изменения 0.2

- Исправлена потеря связи «значение — канал»: совместное нелинейное кодирование
  до объединения источников и регрессионный тест на перестановку значений.
- `AdaptiveWeatherModel`: направленные сообщения с расстоянием, геометрией,
  проекцией ветра, рельефом и физическими индикаторами восстановленного состояния.
- Восемь скрытых позиций вместо обязательных 38 в прогнозном ядре; на выходе
  сохраняются 37 изобар 1000–1 гПа и поверхность. Доступны K=4/8/16/38.
- Собственный фоновый анализ и учёт уже усвоенных версий сообщений. Окна не
  приводят к повторному усвоению одинаковых данных. Шаг памяти строго проверяется.
- Фиксированная z-нормализация по статистикам реанализа, импорт GraphCast,
  контроль единиц/уровней/интервалов, происхождения и SHA256. Смена норм делает
  контрольные точки несовместимыми; онлайн-пересчёт не выполняется.
- Гидростатическая дополнительная ошибка и отдельный консервативный оператор
  обмена. Полный водный/энергетический бюджет сети ещё не реализован.

Физическая адаптация — изменение активаций механизмов в зависимости от состояния,
а не автоматическое переобучение, смена норм или перестройка сетки при прогнозе.
Маски наблюдений, целей, рельефа и области продукции остаются независимыми.

## Установка и проверка без Docker

Python 3.10+; испытаны Python 3.13 и PyTorch CPU в локальной среде.

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install 'torch>=2.2,<3' --index-url https://download.pytorch.org/whl/cpu
python -m pip install -e '.[test,data]'
python -m pytest -q

# Синтетическая проверка адаптивного ядра, обратного распространения и +72 ч.
python -m global_weather.adaptive_cli --output outputs/adaptive

# Геометрия и исходный сравнительный вариант.
global-weather grid --mesh-level 3 --output outputs/grid
global-weather demo --mesh-level 1 --horizon-hours 72 --output outputs/baseline
```

`adaptive_cli` намеренно использует только явно синтетические наблюдения,
пустые демонстрационные статические поля и случайные веса. Его результаты —
проверка исполнения, не метеорологический прогноз. Штатного режима выдачи
необученной сети по реальным данным нет.

## Климатическая основа z-нормализации

Базовый источник: опубликованные статистики ERA5 из семейства GraphCast в
официальном репозитории WeatherNext. Это μ/σ, не веса чужой нейросети и не
локальные сезонные климатические карты. Код источника закреплён ревизией;
численные файлы хранятся отдельно и требуют собственной фиксации хэшей.

```bash
python -m global_weather.import_climatology \
  --download data/normalization/upstream \
  --output data/normalization/graphcast_base.json
```

Загрузка — отдельная подготовительная операция. В рабочем расчёте используются
локальные файлы. **В этой ревизии реальные облачные NetCDF не получены и не
включены в репозиторий.** Импорт испытан на помеченных синтетических файлах;
пути источников, схема и переменные проверены по GitHub.

Базового файла недостаточно для всех наших величин: нужны собственные нормы
Td2, ps, облачности, осадков за 3 часа и каждого спутникового канала.
Отсутствующие нормы не подменяются константами. Нормы 6-часовых осадков не
масштабируются произвольно под 3-часовой шаг. [Порядок получения и подключения](docs/NORMALIZATION.md).

Основные модули: `adaptive.py` — новая модель; `model.py` — сравнительная;
`normalization.py`, `import_climatology.py` — статистики; `physics.py` — физические
компоненты; `checkpoints.py` — проверка совместимости; `observations.py` — данные.

`configs/adaptive_v2.json` фиксирует целевой эксперимент, но не является
автоматическим обучающим конвейером. Полные адаптеры SatDump, пространственные
кодировщики снимков, антенный оператор МТВЗА, реальный архив и обученные веса
ещё требуются. HEALPix закреплён для сравнения, не объявляется реализованным.
