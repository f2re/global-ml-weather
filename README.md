# global-ml-weather

Глобальная исследовательская модель: наблюдения за 12 часов → состояние
атмосферы → прогноз до 72 часов. Источники: разреженные станции и аэрология,
«Электро-Л», «Арктика-М», «Метеор-М» МСУ-МР/МТВЗА. Геометрия — двойственная
икосаэдрическая сетка, преимущественно гексагоны и 12 пятиугольников, не H3.

**Версия 0.3.1. Обученных метеорологических весов и подтверждённой точности нет.**
Есть физически обусловленное ядро, локальный стенд и мосты к пользовательским
проектам. Синтетические результаты не являются прогнозом погоды.

## Совместимость с Арктикой и пользовательской веткой SatDump

`configs/upstream_contracts.json` фиксирует исходники `f2re/arktika-worker`
main и `f2re/SatDump` release/1.2.2, включая точные commit/blob SHA.
Добавлены три локальных модуля:

- `connectors.project_bridge`: read-only catalog.sqlite и download.json
  Арктики; dataset.json, product.cbor, каналы/времена/статусы SatDump.
- `connectors.physical_bridge`: проверенный числовой GeoTIFF, попиксельная
  геометрия и рецензия → физический JSONL контракта модели, без подмены DN=K.
- `connectors.preflight`: контроль ревизий, хэшей и обязательных агентских
  файлов, с ненулевым кодом при расхождении или отсутствии проверки.

[Матрица совместимости, команды и контракт экспорта](docs/PROJECT_COMPATIBILITY.md).
Чтение нативного продукта не является автоматической калибровкой. MTVZA/hrpt30
пока не допускается к точечному экспорту без антенного оператора. В проверенной
Арктике каталог ARCM-only: файл спектральных характеристик Электро-Л не равен
загрузчику его архива. Для Электро-Л предусмотрен путь SatDump/msu_gs.
Реальные файлы оператора и установленный бинарник этой проверкой не испытаны.

## Интерфейс испытаний

```bash
# В существующей среде Python 3.10+ с CPU-версией PyTorch:
python -m pip install -e '.[test,data,lab,compat]'
python -m global_weather.lab.app --workspace outputs/lab --port 8765
```

Открыть http://127.0.0.1:8765. Docker, Node.js, CDN и внешние карты не нужны.
Установщик: `bash scripts/install-lab.sh`; режим `--offline` требует заранее
собранного совместимого WHEELHOUSE. Это не готовый офлайн-пакет зависимостей.

Стенд запускает исходный/адаптивный граф на 12–642 ячейках, до +72 ч, с выбором
D/K, зерна, исключения источников и синтетической проверки оптимизатора.
Есть очередь, отмена, таймаут, протокол и история. Результат: вращаемая сфера,
выбор поля/изобары/срока/ячейки, вертикальный профиль, физические диагностики.
Независимые цели отсутствуют — качество погоды не измерено, RMSE не выдумывается.

Вкладки: испытания, источники данных, агенты разработки и протоколы. Файлы
поступают в локальный входной каталог без перезаписи; инспекция структуры
не объявляется проверкой калибровки. Сеть из веб-интерфейса не запускается.
Новые мосты работают отдельными локальными командами, не произвольным shell API.
Подробнее: [LAB.md](docs/LAB.md).

## Модель

`AdaptiveWeatherModel`: совместное кодирование значения и канала; направленные
графовые сообщения с геометрией и физическими признаками; 8 скрытых позиций
колонки и выход на все 37 изобар 1000–1 гПа; собственный фоновый анализ и
защита от повторного усвоения. Адаптация означает изменение активаций по
состоянию, а не онлайн-переобучение или автоматическое сгущение сетки.

Фиксированные z-нормы реанализа используются согласованно для входов, выхода
и ошибки. Базовый источник GraphCast/ERA5 закреплён в
`configs/normalization_sources.json`. Нужны реальные проверенные файлы и
недостающие нормы Td2, ps, облачности, 3-часовых осадков и спутниковых каналов.
Климатическая норма не заменяет отсутствующее наблюдение. Инженерные масштабы
допустимы только в явно синтетических проверках.

Гидростатическая дополнительная ошибка и отдельный консервативный оператор
обмена есть; полный водный/энергетический бюджет, HEALPix-конкурент, спутниковые
пространственные кодировщики и антенный оператор пока не реализованы.
[Принятые решения](docs/decisions/0002-physically-adaptive.md).

## Коннекторы и агенты

[Коннекторы](docs/CONNECTORS.md): native Арктика/SatDump, физический GeoTIFF,
JSONL, GraphCast, NOAA ISD CSV, ERA5 CDS. Сетевая загрузка только отдельной
командой с --network; исходники и хэши сохраняются. Геопортальный API и полная
радиометрическая обработка не объявляются готовыми.

[Девять ролей](agents/README.md): координатор, данные, радиометрия, нормализация,
физика, модель, исполнение, верификация и аудит выпуска. Инструкции находятся
в AGENTS.md, agents/AGENTS.md, agents/*.md и .claude/agents/*.md. У исполнителя,
верификатора и аудитора обязательные проверки, стоп-условия и отдельный отчёт.
[Пятый протокол](docs/protocols/05-project-compatibility.md) обязателен для всех.
Автономные LLM не запускаются; инструкции не являются ОС-песочницей.

```bash
python -m global_weather.connectors.preflight --project-root . \
  --arktika-source /path/to/arktika-worker --satdump-source /path/to/SatDump \
  --report outputs/check-001/preflight.json
python -m global_weather.lab.agents
python -m global_weather.lab.agents --role executor --action adaptive --execute \
  --workspace outputs/agent-check
```

## Проверки

```bash
python -m pytest -q
python -m global_weather.adaptive_cli --output outputs/adaptive
python -m pip install -e '.[browser]'
python -m playwright install chromium
python scripts/browser-test.py
```

В CI тестируются Python 3.11/3.13, Chromium и отдельные pinned upstream
checkouts. Последний контроль сравнивает контрактные файлы без исполнения кода
поставщиков; зелёный CI не удостоверяет реальную радиометрию и качество погоды.

Реальное численное сравнение доступно отдельно: `global_weather.lab.evaluate`
требует сопоставленные прогноз/цели, маски, площади и манифест с SHA256.
Наличие метрик не удостоверяет независимость периода без научного аудита.
