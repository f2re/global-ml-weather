# global-ml-weather

Глобальная исследовательская модель погоды. Версия 0.3.1.

Модель использует наблюдения за последние 12 часов. Она восстанавливает состояние атмосферы и рассчитывает прогноз до 72 часов.
Наземные сообщения и аэрологические профили могут быть неполными.

**Обученных метеорологических весов и подтверждённой точности пока нет.**
Синтетический расчёт проверяет программу. Он не является прогнозом погоды.

## Назначение

Источники наблюдений: станции, радиозонды, «Электро-Л», «Арктика-М» и «Метеор-М» с МСУ-МР и МТВЗА.
Внутренняя сетка охватывает Землю. Она содержит преимущественно шестиугольные ячейки и 12 пятиугольников. Это не H3.

Адаптивное ядро меняет обмен признаками в зависимости от восстановленного физического состояния.
По умолчанию колонка содержит восемь скрытых позиций. Выход содержит 37 изобарических уровней от 1000 до 1 гПа и приземные величины.
Маска области выдачи не обрезает глобальное состояние.

## Установить стенд

Требования: Linux, отдельный Python 3.10+ и CPU-сборка PyTorch.
Не заменяйте системный Python Astra. Docker и Node.js для работы не нужны.
Установка зависимостей требует разрешения оператора и доступа к сети либо подготовленного каталога пакетов.

1. Создайте отдельное окружение.

```bash
python3 -m venv .venv
. .venv/bin/activate
```

2. Установите зависимости в это окружение.

```bash
python -m pip install 'torch>=2.2,<3' --index-url https://download.pytorch.org/whl/cpu
python -m pip install -e '.[test,data,lab,ecosystem]'
```

3. Выполните тесты.

```bash
python -m pytest -q
```

Ожидаемый результат: все обязательные тесты проходят. Для проверки GeoTIFF требуется установленный `rasterio`.
Если тест завершился ошибкой или обязательная проверка пропущена, остановите приёмку.

Установщик `scripts/install-lab.sh` выполняет отдельный сценарий установки.
Его режим `--offline` требует совместимого `WHEELHOUSE`. Готовый набор всех пакетов в репозиторий не включён.

## Запустить интерфейс

```bash
python -m global_weather.lab.app --workspace outputs/lab --port 8765
```

Откройте `http://127.0.0.1:8765`.
Не публикуйте этот стенд в интернет. Для удалённой работы используйте собственный аутентифицированный SSH-туннель.

Стенд запускает исходный или адаптивный граф на тестовых сетках из 12–642 ячеек.
Он показывает поля на сфере, сроки, изобары, профили, физические диагностики и журнал.
Очередь выполняет задачи последовательно. Пользователь может отменить задачу.

Параметры `D`, `K` и зерно генератора задают конфигурацию испытания.
Страница, скрипты и графика работают локально. Внешние карты и облачные языковые модели не используются.

При отсутствии независимых целей стенд не рассчитывает точность погоды.
Описание форматов результатов и ограничений: [стенд испытаний](docs/LAB.md).

## Подключить существующие проекты

| Источник | Реализованный вход | Граница проверки |
|---|---|---|
| `arktika-worker` | `product.json`, `values.tif`, `quality.tif` | Численные ИК-каналы 4–10; без повторной шкалы |
| Загрузчик GPTL | Локальный L2IR, метаданные и `.download.json` | Требуются подтверждённые время, канал и геометрия |
| SatDump `release/1.2.2` | `dataset.json`, `product.cbor`, файлы каналов | Чтение контейнера не подтверждает радиометрию |

Проверенные ревизии записаны в `configs/ecosystem_sources.json`.
Они не удостоверяют версию установленного бинарного файла.
МТВЗА требует физической калибровки, таблицы каналов и антенного оператора.

```bash
python -m global_weather.compatibility satdump /path/to/output/dataset.json --require msu_mr mtvza
```

Замените пример пути своим каталогом.
Статус `native_transport_only` означает проверку структуры, а не допуск в модель.
Порядок импорта: [совместимость проектов](docs/ECOSYSTEM.md).

## Подготовить нормы

Модель использует фиксированную z-нормализацию. Базовый источник — опубликованные статистики ERA5 семейства GraphCast.
Это средние и стандартные отклонения по уровням, а не веса чужой сети или локальная сезонная климатология.

```bash
python -m global_weather.import_climatology \
  --download data/normalization/upstream \
  --output data/normalization/graphcast_base.json
```

Команда выполняет явную сетевую загрузку. Во время прогноза используются локальные файлы.
Фактические численные статистики в этой ревизии не загружены и не включены в репозиторий.

Базовые нормы не покрывают все переменные проекта.
Для Td2, приземного давления, облачности, трёхчасовых осадков и каждого спутникового канала нужны нормы обучающей выборки.
Не заменяйте отсутствующие нормы вымышленными коэффициентами.
Порядок проверки: [нормализация](docs/NORMALIZATION.md).

## Использовать агентов

Инструкции девяти ролей находятся в `agents/`. Определения Claude Code находятся в `.claude/agents/`.
Все роли обязаны соблюдать `GLOBAL-WEATHER-OPS-1` и профиль документации `RU-TECH-1`.

```bash
python -m global_weather.lab.agents
python -m global_weather.lab.agents --role executor --action adaptive --execute --workspace outputs/agent-tests
```

Программный диспетчер выполняет разрешённые действия. Он не запускает автономную группу языковых моделей.
Для разных управляющих процессов используйте разные рабочие каталоги.
[Роли](agents/README.md) · [обязательный контракт](agents/OPERATING_CONTRACT.md).

## Проверки и статус

```bash
python -m pytest -q
python -m global_weather.adaptive_cli --output outputs/adaptive
python scripts/check_docs.py --strict
```

Браузерная проверка требует дополнительной подготовки Playwright:

```bash
python -m pip install -e '.[browser]'
python -m playwright install chromium
python scripts/browser-test.py
```

CI проверяет Python 3.11 и 3.13, браузер, закреплённые файлы поставщиков и документацию.
Статус проверки относится к конкретному коммиту. Проверяйте итоговый SHA, а не прежний успешный запуск.

Полный водный и энергетический бюджет, обученный HEALPix-вариант и оперативный выпуск пока не реализованы.
Гидростатическая ошибка и отдельный консервативный оператор не подтверждают физическую полноту всей сети.
